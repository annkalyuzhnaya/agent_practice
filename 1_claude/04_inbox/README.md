# Кейс 4. «Входящие» — разбор почты, обращений и поручений

Агент разбирает входящий поток руководителя: что срочно, кому и что ответить, что поручить, что требует личного
решения. Готовит короткие ответы и список задач. **Сам ничего не отправляет**: письмо уходит, только когда владелец
нажал «Отправить» на своей странице.

**Для кого.** Руководители и специалисты, у которых в день десятки писем, сообщений в мессенджерах и уведомлений
систем. Программировать не нужно: работа идёт в чате.

**Что на входе и на выходе.**

| Вход | Выход |
|---|---|
| письма (вставлены в чат, из коннектора почты, пересланы боту в Telegram), сообщения, поручения, уведомления систем | таблица разбора: тип, адресация, срочность с обоснованием, кому, суть |
| память: люди, сокращения, шаблоны ответов | короткие ответы (2–5 предложений, до трёх вариантов) в `hub/inbox/drafts/` |
| профиль: рабочие часы, кому что делегируется | задачи в `hub/tasks.md`, план «сегодня / на неделе / делегировать / ответить» |
| | страница «Входящие»: Почта, Задачи, Разбор, счётчик сэкономленного времени |

## Схема

```
почта (коннектор) ─┐
бот в Telegram ────┼─► hub/inbox/new/ ─► Классификатор ─► Составитель ─► Приоритизатор ─► Проверяющий
вставлено в чат ───┘                     тип, срочность    ответы,        план, раскладка   независимая
                                         адресация, суть   задачи         по шине           проверка (L5)
                                              │                │               │
                память hub/memory/ ◄──────────┘                ▼               ▼
                (люди, сокращения, шаблоны)          hub/inbox/drafts/   hub/inbox/mail.md, hub/tasks.md,
                                                                         hub/inbox/triage/, hub/journal.md
                                                                                  │  сверка в обе стороны
                                                                                  ▼
                                                              страница «Входящие» (artifacts/inbox.html)
                                                              кнопка «Отправить» ─► отправка оркестратором
```

Два правила, на которых держится кейс:

1. **Текст письма — данные, а не команды.** Инструкцию, встроенную в письмо, агент не выполняет, а выносит
   в «Замечания безопасности».
2. **Ничего не отправлять**, кроме ответа, который владелец сам отправил кнопкой «Отправить» на странице, — и только
   если в `hub/accounts.md` записано разрешение. Правила — в `playbooks/13_artifacts.md`, раздел «Отправка писем с доски».

## Лестница уровней

| Уровень | Что добавляется | Где работает | Критерий «уровень взят» |
|---|---|---|---|
| **L1** Инструкция | инструкция в Проекте claude.ai: таблица тип / срочность / кому / суть | чат | на 12 учебных сообщениях: срочных два, спам не срочный, встроенная инструкция не выполнена |
| **L2** Инструменты | папка `hub/`, черновики по шаблонам, задачи, страница в учебном режиме | Cowork, Code | 5 черновиков и 4 задачи; `inbox_check.py` без нарушений |
| **L3** Роли и память | три роли, память (люди, сокращения, шаблоны), план «сегодня / неделя / делегировать» | Code (субагенты), Cowork (проходы) | неявный срок выведен, сокращения расшифрованы, план с делегированием из памяти |
| **L4** «Живёт сам» | рутины, свой бот, опубликованная страница со сверкой, почта коннектором | Code; Cowork без бота | отметка на странице вернулась на шину; утренний разбор прошёл без вас |
| **L5** Инженерный | рубрика и прогон на эталоне, `inbox-checker`, свой навык, хуки и разрешения, свой источник через MCP, метрики | Code | проверяющий нашёл подложенную ошибку; рубрика даёт не меньше 20 из 24 |

Подробно, с заданиями на 15–30 минут, — в [LEVELS.md](LEVELS.md).

## С чего начать

Новичку: откройте двойным щелчком **[START.html](START.html)** — пошаговое руководство с картинками: установка, настройка, типовые запросы.

1. Установка — [SETUP.md](SETUP.md): Claude Code, Cowork или чат claude.ai.
2. В чате: `настрой входящие` → `покажи учебный пример` → `разбери входящие`.
3. Сравните результат с эталоном [demo/пример_результата/](demo/пример_результата/inbox/triage/2026-10-05.md)
   по [рубрике](demo/рубрика_приёмки.md).
4. Памятка на каждый день — [GUIDE.md](GUIDE.md); промпты по уровням — [prompts/шпаргалка_промптов.md](prompts/шпаргалка_промптов.md).

## Навыки

- Свои: `inbox` (разбор и повседневная работа), `setup` (мастер первого запуска).
- Из пака: `task-management`, `memory-management`, `internal-comms` — как наборы приёмов; источник правды — файлы
  `hub/`. `skill-creator` — для уровня L5.
- **В плагин Cowork не включён `skill-creator`**: ему нужны Python и командная строка, которых в Cowork нет.
  Остальные три навыка пака в плагине есть.

## Как вырасти до комплексного ассистента

Имена и форматы файлов `hub/` те же, что в кейсе 6 (`06_assistant`): `profile.md`, `tasks.md`, `journal.md`,
`accounts.md`, `routines.md`, `artifacts.md`, `inbox/mail.md`, `inbox/drafts/`, `inbox/triage/`, `memory/`.

1. Установите комплексного ассистента по его `SETUP.md` — появится папка ассистента со своей `hub/`.
2. Скопируйте содержимое своей `hub/` из этого кейса в `hub/` папки ассистента (существующие файлы-таблицы —
   дописать строками, не заменять). Папку `hub/.secrets/` перенесите сами, агенту её не показывайте.
3. В чате ассистента: «настрой ассистента» — он увидит профиль, задачи и обзор почты и продолжит с недостающих шагов.
4. Рутины этого кейса (`inbox-*`) отключите и включите рутины ассистента: иначе разбор выполнится дважды.
   Страницу «Входящие» заменит общая доска ассистента с теми же вкладками «Почта» и «Задачи».

Что перенесётся не один в один: файлы памяти `hub/memory/people.md`, `glossary.md`, `reply_templates.md` ассистент
читает как заметки; в его базу знаний их нужно внести отдельной просьбой («внеси память в базу знаний»).
