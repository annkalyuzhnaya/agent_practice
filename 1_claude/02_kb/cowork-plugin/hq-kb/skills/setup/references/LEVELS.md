# База знаний — уровни и задания

Агент осваивается по шагам. На каждом уровне — одно задание на 15–30 минут и понятный признак «уровень взят».

На всех уровнях действует стандарт курса:
- итоговый ответ построен так: `ЗАДАЧА → КАК РАБОТАЛ → РЕЗУЛЬТАТ → ЧТО ОСТАЁТСЯ ЧЕЛОВЕКУ`
  (на короткий вопрос к базе допустим короткий ответ: 2–6 строк со ссылками и строка «Проверка: …»);
- в конце работы появляется строка бортжурнала `hub/journal.md`:
  `| дата | агент | что сделано | агент, мин | вручную, мин | где запущен |`
  (на L1 агент выводит эту строку в чат — сохраните её у себя).

Нет ответа в такой форме или строки в журнале — задание не засчитано, даже если результат хороший.

## Уровни одной таблицей

| Уровень | Что добавляется | Где работает | Задание | Признак «взят» |
|---|---|---|---|---|
| L1. Проект | ответы по загруженным материалам со ссылкой | чат claude.ai | три вопроса на учебном наборе | ссылка, две версии, «в базе нет» |
| L2. Папка и Obsidian | рабочая папка, поиск, ссылки `[[…]]`, рубрика приёмки, страница в учебном режиме | Cowork, Claude Code | пять вопросов и приёмка по рубрике | совпало с эталоном, рубрика пройдена |
| L3. Агент ведёт базу | входящее, шаблоны, связи, противоречия, словарь памяти, Проверяющий, уход | Cowork (урезано), Claude Code | оформить заметку, поймать и закрыть противоречие | заметка связана; строка журнала закрыта вашим решением |
| L4. Живёт сам | рутины, бот Telegram, страница с хранилищем, правила доступа | Claude Code; Cowork — частично | включить «Минимум», вернуть решение со страницы | решение дошло до файлов без вашего участия в переносе |
| L5. Инженерный | проверочные вопросы, Проверяющий под нагрузкой, свой навык, хуки, MCP, метрики | Claude Code | один из шести блоков | изменение подтверждено прогоном на эталоне |

## L1. Проект claude.ai: ответы со ссылкой

**Что добавляется.** Инструкция, которая запрещает агенту отвечать «из головы».

**Где работает.** Чат claude.ai (Проект). Папка и установка не нужны.

**Задание (12–15 минут).**
1. Создайте Проект и вставьте инструкцию из [prompts/L1_инструкция_для_проекта.md](prompts/L1_инструкция_для_проекта.md).
2. Загрузите в материалы проекта десять файлов из `demo/hub/kb/` (все подпапки).
3. Задайте три вопроса: «Когда стартует пилот СЭД и в каких отделах?», «Какой срок согласования документов?»,
   «Какой бюджет пилота системы „Маршрут“?».
4. Сравните с [demo/пример_результата/ответы_на_вопросы.md](demo/пример_результата/ответы_на_вопросы.md).

**Уровень взят, если:** на первый вопрос есть ссылка на файл и раздел; на второй показаны **обе** версии (5 и 3 дня)
без выбора за вас; на третий — «в базе этого нет».

**Типичная ошибка.** Вопрос задан в обычном чате, а не внутри Проекта: агент отвечает общими словами и без ссылок.

**Что остаётся человеку.** Открыть источник по ссылке и убедиться, что там сказано именно это. Решить, какая версия срока верна.

## L2. Папка и Obsidian: поиск по заметкам и приёмка по рубрике

**Что добавляется.** Рабочая папка `hub/`, поиск по базе (в Claude Code — локальный индекс), ссылки вида `[[заметка]]`,
просмотр в Obsidian, рубрика приёмки ответа, страница «База знаний» в учебном режиме.

**Где работает.** Claude Code — полностью. Cowork — поиск чтением файлов. Чат без папки — нет.

**Задание (20–25 минут).**
1. Установите кейс по [SETUP.md](SETUP.md) и напишите `настрой` → «Быстрый старт» → «Учебные примеры».
2. Откройте папку `hub` в Obsidian (раздел 3 инструкции), посмотрите «Главную» и граф.
3. Задайте пять вопросов из [demo/README.md](demo/README.md).
4. Попросите: «Проверь свои ответы по рубрике приёмки из LEVELS.md и покажи таблицу».
5. Откройте `artifacts/kb.html` двойным щелчком: посмотрите обзор, карту и вкладку «Противоречия».

**Рубрика приёмки ответа**

| № | Критерий | Как проверить |
|---|---|---|
| 1 | У каждого утверждения есть ссылка `[заметка § раздел]` | в ответе нет фраз без ссылки, кроме пометок «не подтверждено» |
| 2 | Ссылка ведёт на существующую заметку, и в ней это действительно сказано | открыть заметку в Obsidian |
| 3 | Расхождение показано обеими версиями с датами | вопрос 1 набора |
| 4 | На вопрос без ответа сказано «в базе этого нет» | вопрос 5 набора |
| 5 | Сокращение расшифровано по словарю, а факт взят из базы | вопрос 3 набора («СК») |
| 6 | Вопрос и ответ записаны в `hub/kb/_вопросы.md`, есть строка бортжурнала | открыть файлы |

**Уровень взят, если:** все пять ответов совпали с эталоном по смыслу и источникам, рубрика пройдена по шести пунктам.

**Типичная ошибка.** Принять ответ, потому что он «похож на правду», и не открыть ни одной ссылки.

**Что остаётся человеку.** Выборочно открывать источники. Следить, что кладётся в базу.

## L3. Агент ведёт базу: заметки, связи, противоречия

**Что добавляется.** Приём материалов через `hub/kb/входящее/`, заметки по шаблонам, связи, журнал противоречий,
словарь памяти (навык `memory-management`), независимый Проверяющий, уход за базой.

**Где работает.** Claude Code — полностью (субагенты `librarian` и `kb-verifier`, скрипт ухода). Cowork — то же
последовательными проходами: проверка вторым проходом, уход вручную по правилам. Чат без папки — нет.

**Задание (25–30 минут).**
1. «разбери входящее» — учебная заметка после разговора с юристом станет заметкой базы. Проверьте: тип, теги, источник,
   ссылки на родственные заметки, строка «Оформлено» в исходнике.
2. Агент спросит про сокращения из заметки (ДС, КЭП). Ответьте — и проверьте, что они появились в `hub/memory/glossary.md`,
   а не в базе.
3. «есть ли противоречия?» — должно быть расхождение по сроку согласования. Попросите агента объяснить, почему он
   не выбрал версию сам.
4. Закройте противоречие своим решением: «верна версия А: правка регламента не утверждена». Проверьте строку
   в `hub/kb/_противоречия.md`: статус `закрыто: …` с пометкой, что решение ваше.
5. «наведи порядок в базе» — посмотрите список ухода. Одобрите исправление битой ссылки, заметку без связей оставьте как есть.
6. Сравните с эталоном в [demo/пример_результата/](demo/пример_результата/).

**Уровень взят, если:** новая заметка оформлена по шаблону и связана минимум с одной заметкой; сокращения лежат в памяти;
противоречие закрыто только после вашего слова; в списке ухода исправлено только одобренное.

**Типичная ошибка.** Сказать «исправь всё сам» — и получить базу, где версия выбрана за вас. Агент обязан отказаться
закрывать противоречие без решения; если не отказался — это повод поправить плейбук.

**Что остаётся человеку.** Доверять базе, но проверять спорные связи. Решать, какая версия верна. Не класть в базу лишнее.

## L4. «Живёт сам»: расписание, бот, страница с хранилищем

**Что добавляется.**
- **Рутины**: набор «Минимум» (`kb-inbox`, `kb-care`) или «Стандарт» (плюс `kb-index`, `kb-tg-pull`, `kb-weekly`).
- **Свой бот Telegram**: «запомни …» и пересланное — во входящее; вопрос — ответ со ссылкой; сводка недели.
- **Страница «База знаний» с хранилищем**: ваши кнопки возвращаются агенту при сверке.
- **Правила доступа** в `hub/accounts.md`: что подключено и что агенту разрешено. Почта и календарь этому кейсу не нужны;
  единственный внешний канал — ваш бот.

**Где работает.** Claude Code — всё. Cowork — страница (если доступна публикация) и рутина `kb-inbox` (если есть расписание);
бот и остальные рутины — нет.

**Задание (30 минут).** Порядок — в [SETUP.md](SETUP.md), разделы 4–6.
1. «опубликуй страницу» → откройте её, закрепите. Убедитесь, что вверху «Сверено с ассистентом: …».
2. Положите учебные примеры заново (если убрали) и на вкладке «Противоречия» нажмите «Верно А» с комментарием.
3. «сверь страницу» — проверьте, что в `hub/kb/_противоречия.md` строка закрыта «решение владельца со страницы»,
   а на странице пропала пометка «ждёт ассистента».
4. «включи рутины» → «Минимум». Проверьте строки в `hub/routines.md`.
5. По желанию: «подключи бота» → отправьте боту `запомни проверить срок договора` и вопрос «когда стартует пилот?» →
   «проверь бота». Заметка должна лечь во входящее, ответ со ссылкой — прийти в Telegram.
6. Откройте `hub/accounts.md`: что записано в колонке «Что агентам разрешено»?

**Уровень взят, если:** решение, принятое кнопкой на странице, оказалось в файле без вашего ручного переноса; хотя бы одна
рутина отработала и оставила дату в `hub/routines.md`; (если бот подключён) бот ответил со ссылкой на заметку.

**Типичная ошибка.** Ждать от бота мгновенного ответа: он отвечает после опроса. Вторая — оставить в комментарии на странице
поручение («удали старую заметку»): комментарий — это данные, поручением считается только кнопка.

**Что остаётся человеку.** Раз в неделю смотреть вкладки «Противоречия» и «Уход». Токен бота хранить самому.
Не открывать доступ к странице другим без нужды.

## L5. «Инженерный»: качество и расширение

**Что добавляется.** Способы убедиться, что агент не стал хуже после ваших правок, и способы расширить его.

**Где работает.** Только Claude Code, сессия в папке кейса.

**Задание (по 20–30 минут на блок; для зачёта достаточно одного).**

**Блок 1. Проверочные вопросы «вопрос → ожидаемый источник».**
1. `python tools/kb_eval.py` на учебном наборе — должно быть 4 из 4.
2. Составьте 5–8 вопросов по своей базе в формате [demo/evals.json](demo/evals.json), сохраните в `hub/kb/_evals.json`.
   Один вопрос — заведомо без ответа (`"expect": []`).
3. `python tools/kb_eval.py --file hub/kb/_evals.json`. Не прошёл вопрос — разберитесь: нет заметки, другое слово
   (добавьте в словарь) или плохой заголовок.
4. Вопросы без ответа проверьте в чате: агент должен сказать «в базе нет».
Скрипт проверяет поиск, а не ответ; ответ принимается по рубрике из L2.

**Блок 2. Проверяющий под нагрузкой.** Дайте субагенту `kb-verifier` заведомо неверный ответ: «Срок согласования —
3 рабочих дня [demo_регламент-согласования-документов § 3]». Он обязан вернуть «не подтверждено» с цитатой из регламента.
Затем усложните: верный факт с неверной ссылкой. Если пропустил — уточните раздел «Проверяющий» в `playbooks/02_kb.md`
и пересоберите (`python tools/build.py`).

**Блок 3. Свой навык через `skill-creator`.** Например, «справка по контрагенту»: по имени собирает из базы карточку,
решения и открытые вопросы со ссылками. Скажите: «создай навыком skill-creator навык „справка по контрагенту“; источник
фактов — только `hub/kb/`; формат ответа — как в `playbooks/02_kb.md`». Проверьте на «Северном контуре». Навык ляжет
в `.claude/skills/`; чтобы он попал в плагин Cowork, добавьте его в таблицу `SKILLS` в `tools/build.py`.

**Блок 4. Разрешения и хуки Claude Code.** Откройте `.claude/settings.json`: там разрешены скрипты кейса и запрещено
чтение `hub/.secrets/`. Добавьте хук, который после каждой записи в `hub/kb/` пересобирает индекс
(`PostToolUse` для `Write|Edit` → `python tools/kb_index.py build`), — попросите агента показать формат командой `/hooks`.
Проверка: добавьте заметку и сразу найдите её поиском без «пересобери индекс».

**Блок 5. Свой источник и доступ через MCP.** Два направления, оба необязательны:
- *база как источник для других агентов:* сервер MCP даёт доступ к `hub/kb/` только на чтение (поиск и чтение заметки) —
  так базой сможет пользоваться, например, агент подготовки к встречам. Сервер в кейс не входит: опишите агенту, какие
  два действия нужны, и попросите собрать его на основе `tools/kb_index.py`;
- *внешнее хранилище как источник:* навыки Desktop Commander `obsidian-vault` и `knowledge-base` (каталог плагинов,
  см. [SETUP.md](SETUP.md), раздел 8) позволяют работать с хранилищем Obsidian вне папки кейса. Правило прежнее:
  в ответ попадает только то, на что есть ссылка.
Сюда же — официальный плагин `telegram` вместо моста `tg_bridge.py`.

**Блок 6. Метрики в бортжурнале и встраивание в кейс 6.** Попросите: «покажи по `hub/journal.md` и `hub/kb/_вопросы.md`
за месяц: число вопросов, долю „в базе нет“, долю „частично“, открыто и закрыто противоречий, минут агента и минут вручную».
Высокая доля «в базе нет» — сигнал, каких материалов не хватает. Затем перенесите `hub/` в комплексного ассистента
по разделу «Как вырасти до комплексного ассистента» в [README.md](README.md).

**Уровень взят, если:** изменение (вопросы, плейбук, навык, хук) подтверждено повторным прогоном: `python tools/kb_eval.py`
не стал хуже, пять вопросов учебного набора по-прежнему совпадают с эталоном.

**Типичная ошибка.** Править сгенерированные файлы в `.claude/` или `cowork-plugin/` — следующая сборка их сотрёт.
Правятся `playbooks/` и таблицы в `tools/build.py`.

**Что остаётся человеку.** Составлять проверочные вопросы и ожидаемые источники: агент не должен сам себе писать экзамен.
Решать, кому давать доступ к базе.
