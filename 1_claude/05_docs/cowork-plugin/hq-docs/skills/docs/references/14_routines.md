# Рутины кейса «Документ-инженер»

Рутина — запуск по расписанию без человека. Она ничего не спрашивает, не принимает решений за человека и не отправляет
файлы наружу: всё спорное оставляет в заявке пометкой `[РЕШИТЬ]`. Создаётся только после явного «да» на каждую рутину;
учёт — в `hub/routines.md`: `| Рутина | Расписание | Что делает | Где создана | Статус | Последний запуск |`.

В подсказках `{ПАПКА}` — полный путь к папке кейса (подставить при создании).

## Рутины

| Рутина | Расписание (cron) | Зачем |
|---|---|---|
| `docs-handoff` | `0 10-18/2 * * 1-5` — каждые 2 часа в рабочее время | обработать новые заявки `hub/handoff/` |
| `docs-weekly` | `0 9 * * 1` — понедельник, 9:00 | недельный отчёт по версиям и проверкам |
| `docs-tg-pull` | `*/20 8-21 * * *` — каждые 20 минут (только если подключён бот) | забрать заявки из Telegram |

### docs-handoff — обработка заявок

```
Рабочая папка: {ПАПКА}. Ты — документ-инженер, действуй по playbooks/05_docs.md и playbooks/00_protocol.md.
1. Если есть hub/.secrets/telegram.json — выполни python tools/tg_bridge.py pull.
2. Если опубликована страница «Документы» (hub/artifacts.md) — сверь её с шиной по playbooks/13_artifacts.md.
3. python tools/handoff.py list. Для каждой заявки со status: new и needs: code без пометок [РЕШИТЬ]:
   Парсер → Генератор → Валидатор (отдельный субагент doc-validator) → при «пройдена» Версионер.
   Двигай этапы через tools/handoff.py stage, закрывай через tools/handoff.py done.
4. Заявки с [РЕШИТЬ] и заявки, где не хватает файлов, не трогай.
5. Проверка не пройдена — версию не сохраняй, этап «отклонено», в результате перечисли задетые разделы.
6. Действующую версию не назначай. Файлы наружу не отправляй.
7. python tools/registry.py export; обнови страницу (шаг 2 «шина → страница»); строка в hub/journal.md.
8. Если подключён бот — по каждой закрытой заявке одно сообщение владельцу:
   python tools/tg_bridge.py send --text "Готово: <заявка>. Проверка пройдена|НЕ пройдена. Версия N|версия не сохранена."
Ничего не спрашивай. Нет новых заявок — заверши молча, без записи в журнал.
```

### docs-weekly — недельный отчёт по версиям

```
Рабочая папка: {ПАПКА}. Действуй по playbooks/05_docs.md (роль Версионер).
1. python tools/versions.py list; python tools/registry.py export.
2. Для каждого документа, у которого за 7 дней появились версии: python tools/versions.py diff <id> и
   python tools/version_report.py <id> (HTML в hub/docs/out/).
3. Запиши hub/docs/out/ГГГГ-ММ-ДД_недельный_отчёт_версий.md: какие документы менялись, что изменилось по разделам
   (словами), какие проверки не пройдены, у каких документов действующая версия не назначена или старее последней,
   какие заявки ждут решения человека дольше 3 дней.
4. Действующую версию не назначай — перечисли, где нужен выбор человека.
5. Строка в hub/journal.md. Если подключён бот — одно сообщение владельцу: «Недельный отчёт по версиям готов: N документов
   менялись, M решений ждут вас» (без файла).
Ничего не спрашивай.
```

### docs-tg-pull — заявки из Telegram

```
Рабочая папка: {ПАПКА}. Выполни python tools/tg_bridge.py pull. Больше ничего не делай: заявки обработает рутина docs-handoff.
```

## Правила

- Создавать средствами среды (задачи по расписанию Claude Code / Cowork). В Cowork рутина `docs-handoff` бессмысленна
  для заявок `needs: code` — там оставляем только сверку страницы; честно сказать об этом человеку.
- Компьютер выключен — рутина не сработает; при следующем запуске заявки обработаются в порядке поступления.
- Отключение: удалить задачу в среде и поставить в `hub/routines.md` статус «отключена».
- Каждая рутина пишет «Последний запуск» в `hub/routines.md`.
