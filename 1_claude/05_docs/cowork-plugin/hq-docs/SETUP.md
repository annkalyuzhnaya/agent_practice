# Установка кейса «Документ-инженер»

Три варианта: **А** — Claude Code (полный конвейер), **Б** — Cowork (сокращённый режим), **В** — Проект в claude.ai (уровень L1).
Начните с того, что у вас есть; варианты не мешают друг другу.

## А. Claude Code — полный вариант

Нужно: Claude Code, Python 3.10+.

1. Откройте папку кейса `05_docs` в Claude Code (именно её, а не папку выше — тогда подхватятся навыки и субагенты из `.claude/`).
2. Скажите: **«настрой»**. Агент выполнит `python tools/setup.py` (создаст рабочую папку `hub/`), задаст 3–4 вопроса о ваших
   документах и предложит остальные шаги. Обязательных шагов два: папка и профиль.
3. Библиотеки Word/Excel — с вашего согласия агент выполнит `pip install -r requirements.txt` (python-docx, openpyxl).
4. Пробный запуск: «загрузи учебный набор и обработай заявки» (`python tools/demo.py load`). Убрать учебные файлы — «убери учебный набор».

Если после правки `playbooks/` нужно пересобрать навыки и плагин: `python tools/build.py`.

## Б. Cowork — сокращённый режим

1. В Cowork: Настройки → Плагины → установить из файла → `dist/hq-docs.plugin`.
2. Выберите рабочую папку (любую свою; удобнее — папку кейса, тогда заявки сразу увидит Claude Code).
3. Скажите: **«настрой»**.

Честно о том, что в Cowork урезано и чем заменено:

| Чего нет в Cowork | Почему | Чем заменено |
|---|---|---|
| Точечная правка раздела большого документа | нужны скрипты Python на компьютере | заявка в `hub/handoff/` с `needs: code` — выполнит Claude Code |
| Проверка целостности по контрольным суммам | то же | проверка глазами по списку, с пометкой «хэш-проверки не было» |
| Запись версий | то же | заявка; читать реестр `hub/docs/registry.md` можно |
| Субагенты | в плагине их нет | роли — последовательными проходами в одном разговоре |
| Telegram-бот | нужен Python и сеть | заявки в чате и на странице «Документы» |
| Навык `skill-creator` | нужны скрипты и CLI `claude` | работает в Claude Code |

Что в Cowork есть: простой документ по шаблону средствами среды, помощь с формулами Excel, подача заявок,
страница «Документы» (публикация и сверка), навыки `build-dashboard`, `data-visualization`, `validate-data`.

**Мост Cowork → Code.** Чтобы заявка из Cowork дошла до Claude Code, обе среды должны видеть одну папку `hub/`:
в Cowork выберите рабочей папкой папку кейса. Если папки разные — перенесите файл заявки из `hub/handoff/` вручную.

## В. Проект в claude.ai — уровень L1

1. claude.ai → Проекты → Создать проект «Документ по шаблону».
2. В инструкции проекта вставьте текст из [prompts/L1_инструкция_проекта.md](prompts/L1_инструкция_проекта.md).
3. В знания проекта положите свой шаблон (текстом или .docx).
4. В чате: вставьте данные и скажите «собери документ по шаблону». Шпаргалка — [prompts/шпаргалка_промптов.md](prompts/шпаргалка_промптов.md).

В чате нет папки, версий и проверки по контрольным суммам; большой документ правьте по одному разделу, вставляя его в чат.

## Навыки `docx` / `xlsx` / `pdf` из каталога Anthropic

В кейс они **не скопированы** (их лицензия не разрешает распространение). Включить их можно самим:

- **Claude Code:** команда `/plugin` → каталог Anthropic → плагин с навыками работы с документами → установить.
- **Cowork и чат claude.ai:** Настройки → Возможности (в некоторых версиях — «Плагины» / «Навыки»); обычно создание
  файлов Word/Excel/PDF там уже встроено и включено.

Названия пунктов меню меняются от версии к версии — ищите раздел про навыки или плагины.

Как кейс работает с ними и без них:

| | С навыками `docx`/`xlsx`/`pdf` | Без них |
|---|---|---|
| Claude Code | агент может ещё и оформлять документ «с нуля», читать PDF-источник | полный конвейер работает на скриптах кейса (`tools/`), навыки не обязательны |
| Cowork | простые документы и таблицы создаются файлами | документ выдаётся текстом/таблицей в чате; файл соберёт Claude Code по заявке |
| Чат | файл можно скачать | текст для вставки в ваш шаблон |

PDF кейс не правит: PDF годится только как источник данных (и только если включён навык `pdf`).

## Навыки кейса

| Навык | Зачем в этом кейсе | Нужен ли ключ / подключение | Как проверить |
|---|---|---|---|
| `docs` | основная работа: шаблон, правка раздела, проверка, версии, заявки | нет | «что ты умеешь с документами?» |
| `setup` | настройка и донастройка по шагам | нет | «настрой» |
| `validate-data` (пак) | приёмы проверки чисел — их использует Валидатор | нет | «проверь числа в отчёте по выгрузке» |
| `build-dashboard` (пак) | страница-отчёт из данных выгрузки (один HTML-файл) | нет; данные — из вашего файла | «сделай страницу-отчёт по выгрузке задач» |
| `data-visualization` (пак) | приёмы для графиков; вызывается из `build-dashboard` | нет | график на странице-отчёте читается |
| `skill-creator` (пак, только Claude Code) | L5: оформить свой шаблон как навык | CLI `claude` для прогона проверок навыка | «создай навык для моего шаблона» |
| `docx` / `xlsx` / `pdf` (каталог) | оформление файлов, чтение PDF | включаются из каталога, см. выше | «создай пустой документ Word» |

Сторонние навыки и лицензии — `pack/THIRD_PARTY.md`.

## Страница «Документы»

Скажите: **«опубликуй страницу документов»**. Агент объяснит, что на неё попадёт (названия документов и разделов,
короткие строки изменений — не тексты документов), и после вашего «да» опубликует `artifacts/docs.html` как приватную
страницу с хранилищем, затем выполнит первую сверку. Дальше: «сверь страницу документов» или кнопка «Сверить сейчас».

Посмотреть страницу без публикации: откройте `artifacts/docs.html` с диска — она покажет учебные данные.
Если публикация недоступна: реестр `hub/docs/registry.md` и локальный отчёт `python tools/version_report.py <id>`.

## Расписание

Скажите: **«поставь на расписание»**. Агент предложит набор, на каждую рутину нужно ваше «да».

| Набор | Рутины |
|---|---|
| минимум | `docs-handoff` — обработка заявок каждые 2 часа в рабочее время |
| стандарт | + `docs-weekly` — недельный отчёт по версиям (понедельник, 9:00); + `docs-tg-pull` — если подключён бот |

Рутины не отправляют файлы и не выбирают действующую версию. Компьютер выключен — рутина не сработает.
Подробности — `playbooks/14_routines.md`.

## Telegram-бот (только Claude Code)

1. В Telegram: @BotFather → `/newbot` → получите токен.
2. Скажите агенту «подключи телеграм». Он создаст заготовку `hub/.secrets/telegram.json`. **Токен вписываете вы сами**
   в поле `token` этого файла; агент файл не открывает и токен в чат не просит.
3. Проверка: `python tools/tg_bridge.py check` → «Бот на связи».
4. Напишите боту `/start`; `python tools/tg_bridge.py whoami` покажет ваш номер — впишите его в `owner_id`. Бот отвечает только вам.
5. Сценарии: перешлите боту текст «обнови раздел 3 в регламенте» (можно с файлом .docx/.xlsx) → появится заявка в `hub/handoff/`;
   после обработки бот напишет «Готово … проверка пройдена / не пройдена, версия N».
6. Рутина опроса `docs-tg-pull` (каждые 20 минут) — по вашему «да».

Что мост умеет с файлами: **принимает** .docx, .xlsx, .xlsm, .json, .md, .txt до 20 МБ (кладёт в `hub/docs/in/`);
фото, голос и прочее не принимает — в заявке появится вопрос. **Отправить** готовый файл может только вам, только из
`hub/docs/out/` и только после вашего явного «да» на этот конкретный файл; рутины файлы не отправляют.

## Проверка «всё работает»

| Что проверить | Команда или фраза | Ожидаемо |
|---|---|---|
| Папка и шаги | `python tools/setup.py status` | шаги 0 и 1 — «сделано» |
| Конвейер | `python tools/evals.py` | «ИТОГ: прошло 11 из 11» |
| Заявки | `python tools/handoff.py list` | список заявок или «заявок нет» |
| Версии | `python tools/versions.py list` | документы и версии |
| Бот (если подключали) | `python tools/tg_bridge.py check` | «Бот на связи» |
| Плагин Cowork | «что ты умеешь с документами?» | перечислены возможности и ограничения Cowork |
