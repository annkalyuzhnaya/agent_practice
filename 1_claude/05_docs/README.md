# Кейс 5. Документ-инженер (Word/Excel)

Агент, который собирает документы по шаблону из данных, точечно правит большие документы, **доказывает, что не задел
лишнего**, ведёт версии и отвечает «что изменилось». Кейс самодостаточный: всё нужное лежит в этой папке.

**Для кого:** для тех, кто ведёт регламенты, отчёты, сводки в Word и Excel и устал сверять глазами «а что ещё поменялось».

**Что остаётся человеку всегда:** утвердить итоговый документ и решить, какая версия действующая.

## Как устроено

```
данные, шаблон, документ                                          человек
        │                                                            ▲
        ▼                                                            │ утверждает, выбирает действующую версию
   ┌─────────┐   ┌───────────┐   ┌────────────────────────┐   ┌───────────┐
   │ Парсер  │──▶│ Генератор │──▶│ Валидатор целостности  │──▶│ Версионер │
   └─────────┘   └───────────┘   │ (независимый)          │   └───────────┘
   структура     новый файл      └────────────────────────┘   версии, сравнение,
   разделов      в hub/docs/out  «изменено только: раздел N»   реестр, страница
```

- **Парсер** превращает файл в разделы с контрольными суммами (`tools/parser.py`).
- **Генератор** заполняет шаблон (`{{ключ}}`, `{{rows:список}}`) или меняет один раздел (`tools/generator.py`).
- **Валидатор** сравнивает «до» и «после» по разделам, ищет незаполненные метки, сверяет числа с источником
  (`tools/integrity_diff.py`, `tools/guard.py`, `tools/numcheck.py`). Он не читает рассуждений Генератора.
- **Версионер** хранит версии, показывает разницу, строит отчёт сравнения и реестр (`tools/versions.py`,
  `tools/version_report.py`, `tools/registry.py`).

Рабочая папка `hub/` создаётся внутри кейса при настройке. Заявки лежат в `hub/handoff/` и проходят этапы
`принято → собрано → проверено → версия`. Заявка с `needs: code` — мост из Cowork в Claude Code: в Cowork её можно
подать, выполнит её Claude Code на компьютере.

## Где что работает

| Возможность | Claude Code | Cowork (плагин `hq-docs`) | Чат claude.ai (Проект) |
|---|---|---|---|
| Документ по шаблону из данных | да, скриптом, с проверкой меток и чисел | простые документы средствами среды | да, текстом по инструкции L1 |
| Точечная правка раздела большого документа | да | нет — оформляется заявка `needs: code` | только фрагмент, вставленный в чат |
| Проверка целостности по контрольным суммам | да | нет — «сверено глазами», честно помечено | нет |
| Версии и «что изменилось» | да | чтение реестра; запись — заявкой | сравнение двух вставленных текстов |
| Помощь с формулами Excel | да | да | да |
| Страница «Документы» | да | да (публикация и сверка) | нет |
| Расписание | да | да, кроме рутин со скриптами | нет |
| Telegram-бот | да | нет (нужен Python) | нет |
| Субагенты (независимый валидатор) | да | нет — роли последовательными проходами | нет |

Навыки пака в Cowork: `build-dashboard`, `data-visualization`, `validate-data` — включены в плагин.
**`skill-creator` в плагин Cowork не включён**: ему нужны скрипты Python и CLI `claude`; он работает в Claude Code (уровень L5).
Навыки Anthropic `docx` / `xlsx` / `pdf` в кейс не скопированы (лицензия) — как включить их из каталога и как кейс
работает без них, написано в [SETUP.md](SETUP.md).

## Уровни

| Уровень | Что добавляется | Где работает |
|---|---|---|
| L1 «Промпт» | документ по фиксированному шаблону, без выдумок | чат, Cowork, Code |
| L2 «Правка с доказательством» | точечная правка раздела + отчёт целостности | Code (в Cowork — заявкой) |
| L3 «Конвейер и версии» | четыре роли, версии, «что изменилось», заявки | Code; Cowork подаёт заявки |
| L4 «Живёт сам» | рутины, Telegram-бот, страница «Документы» | Code + Cowork |
| L5 «Инженерный» | поиск по структуре, эвалы, хук перед записью, свой шаблон и навык | Code |

Подробно, с заданиями и критериями — [LEVELS.md](LEVELS.md).

## С чего начать

Новичку: откройте двойным щелчком **[START.html](START.html)** — пошаговое руководство с картинками: установка, настройка, типовые запросы.

1. [SETUP.md](SETUP.md) — установка: Claude Code, Cowork или Проект в claude.ai.
2. Скажите агенту «настрой» — он проведёт по шагам.
3. [GUIDE.md](GUIDE.md) — фразы на каждый день. [prompts/](prompts/) — инструкция для Проекта и шпаргалка промптов.
4. Учебный набор: `python tools/demo.py load`; образец результата — [demo/пример_результата/](demo/пример_результата/).

## Как вырасти до комплексного ассистента

Этот кейс — одна из ролей личного ассистента (кейс 6, `06_assistant`). Форматы шины совместимы:

- заявки `hub/handoff/*.md` с полями `to`, `needs`, `status` — те же; ассистент кейса 6 может класть сюда заявки
  (`to: docs`), а результат читать из раздела «Результат»;
- папки `hub/docs/in`, `out`, `templates`, `store`, журнал `hub/journal.md`, профиль `hub/profile.md` — те же;
- субагенты `doc-parser`, `doc-generator`, `doc-validator`, `doc-versioner` называются так же, как в кейсе 6.

Путь: освоить L3 здесь → на L5 выполнить задание «встроить в кейс 6» (перенести свой шаблон и хук, сверить, что заявка
из общей доски проходит весь конвейер). Дополнительные поля этого кейса (`stage`, `check`, `doc`, `version`) ассистент
кейса 6 просто игнорирует — они ничего не ломают.

Все данные в кейсе вымышленные. Документы с персональными и закрытыми сведениями в учебном стенде не обрабатываются.
