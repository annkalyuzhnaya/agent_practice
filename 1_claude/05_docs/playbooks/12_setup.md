# Настройка кейса «Документ-инженер»

Настройка адаптивная: сначала выясняем, что умеет среда, потом предлагаем только то, что здесь возможно.
Один шаг — один экран. Вопросы с выбором — формой (`AskUserQuestion`; если формы нет — нумерованный список).
Ничего не включаем, не публикуем и не ставим на расписание без явного «да». Состояние — в `hub/setup.md`.

## Приветствие (один раз)

Если в `hub/setup.md` нет строки `Приветствие: показано ГГГГ-ММ-ДД` — показать 4–5 строк: что это за кейс
(документы по шаблону, точечные правки, версии), что настройка займёт 5–10 минут, что обязательных шагов два,
остальное можно отложить, и что слово «помощь» в любой момент выводит памятку. Записать строку с датой.

## Определить среду и записать таблицу возможностей

| Возможность | Как проверить | Если нет — чем заменено |
|---|---|---|
| Запуск скриптов Python | `python tools/setup.py status` выполняется | Cowork/чат: простые документы средствами среды, тяжёлое — заявкой `needs: code` |
| Библиотеки python-docx, openpyxl | строка «Библиотеки Word/Excel» в `status` | `pip install -r requirements.txt`; до установки — только заявки и реестр |
| Навыки `docx` / `xlsx` / `pdf` | есть в списке навыков среды | работаем скриптами кейса; в чате — текстом и таблицей |
| Публикация страниц (Artifact) | есть инструмент публикации | локальный HTML-отчёт `tools/version_report.py` и `hub/docs/registry.md` |
| Расписание | есть инструмент задач по расписанию | ручной запуск фразой «обработай заявки» |
| Telegram-мост | есть Python и доступ в сеть | заявки через чат и страницу |

Таблицу «возможность → есть/нет → чем заменено» записать в `hub/setup.md` под шагами.

## Шаги

| Шаг | Обязательность | Что делаем | Готово, когда |
|---|---|---|---|
| 0. Рабочая папка и шина | обязательный | `python tools/setup.py` (в Cowork — создать `hub/` из `references/presets` вручную) | есть `hub/` и её папки |
| 1. Профиль документов | обязательный | 3–4 вопроса формой: какие документы ведёте, кто утверждает, правила имён файлов, что нельзя трогать | заполнен `hub/profile.md`, убрана пометка «профиль не заполнен» |
| 2. Библиотеки Word/Excel | желательный (Claude Code) | с согласия: `pip install -r requirements.txt`; проверка `python tools/evals.py` | эвалы «прошло 11 из 11» |
| 3. Навыки docx/xlsx из каталога | необязательный | объяснить, где включить (см. `SETUP.md`), и что кейс работает и без них | записано: включены / не нужны |
| 4. Пробный запуск | желательный | `python tools/demo.py load` → обработать учебную заявку → показать отчёт целостности и версии | человек видел результат; предложить `demo.py clean` |
| 5. Страница «Документы» | необязательный | по правилам `13_artifacts.md`, только после «да» | ссылка в `hub/artifacts.md` |
| 6. Расписание | необязательный | по правилам `14_routines.md`, только после «да» | строки в `hub/routines.md` |
| 7. Telegram-бот | необязательный | по правилам `15_telegram.md`; токен вписывает владелец | `tg_bridge.py check` отвечает «Бот на связи» |

Статусы в `hub/setup.md`: `не начат`, `сделано`, `отложено`, `недоступно в этой среде`. Отложенное не навязывать:
напомнить один раз в конце настройки и по просьбе «что ещё можно настроить».

## Как вести разговор после настройки

- Человек общается только в чате; шину агент ведёт сам. Команд терминала человеку не диктовать — выполнить самому.
- Файл Word/Excel от человека → копия в `hub/docs/in/` (шаблон → `hub/docs/templates/`); оригинал не трогаем.
- Результат показываем в чате: оглавление, изменённый раздел, отчёт проверки, номер версии — и путь к файлу.
- «Помощь» → короткая памятка из `GUIDE.md`.
- Сообщение со страницы с `request: sync_board` — просьба сверить страницу и шину немедленно (`13_artifacts.md`).

## Проверка «всё работает»

`python tools/setup.py status` — шаги отмечены; `python tools/evals.py` — все случаи прошли;
`python tools/handoff.py list` — видны заявки; `python tools/tg_bridge.py check` — бот на связи (если подключали).
