# Документ-инженер: конвейер из четырёх ролей

Задачи: собрать документ по шаблону из данных; точечно обновить раздел большого документа, не задев остальное;
вести версии и отвечать «что изменилось». Конвейер: **Парсер → Генератор → Валидатор целостности → Версионер**.
Каждая роль делает одно дело и передаёт следующей файл и короткую записку. Валидатор независим: он не читает
рассуждений Генератора и судит только по файлам «до» и «после».

Общие правила — в `00_protocol.md` (исходник не трогаем, ничего не выдумываем, действующую версию выбирает человек).

## Когда какая роль

| Просьба человека | Роли |
|---|---|
| «Собери отчёт по шаблону из этих данных» | Парсер (данные, шаблон) → Генератор `fill` → Валидатор (метки, числа) → Версионер |
| «Обнови раздел 3, остальное не трогай» | Парсер → Генератор `update-section` → Валидатор `integrity_diff` → Версионер |
| «Проверь, что коллега менял только раздел 3» | Парсер → Валидатор (Генератор не нужен) |
| «Что изменилось между версиями?» / «покажи историю» | Версионер (`diff`, `version_report`) |
| «Поменяй значения в ячейках» | Генератор `set-cells` → Валидатор (`--allow лист`) → Версионер |
| «Помоги с формулой Excel» | без конвейера: объяснить формулу, проверить на 2–3 строках; файл не менять без просьбы |

## Роль 1. Парсер

Задача: превратить файл в структуру «разделы/листы + таблицы + хэши», чтобы остальные роли говорили о разделах, а не о «где-то в тексте».

- `python tools/parser.py файл.docx` — оглавление с хэшами; `--json` / `--out x.json` — полная структура.
- Раздел .docx = заголовок (стиль «Заголовок N») + всё до следующего заголовка; раздел .xlsx = лист.
  Всё до первого заголовка — «(преамбула)».
- У раздела два хэша: `text_hash` (содержание) и `xml_hash` (содержание + оформление).
- Отдаёт дальше: список разделов, точное название нужного раздела, предупреждения.

Обязан предупредить: в документе нет заголовков-стилей (весь текст — один раздел, точечная правка невозможна);
название раздела встречается дважды; файл не .docx/.xlsx; в шаблоне есть метки, для которых в данных нет ключей.

## Роль 2. Генератор

Задача: собрать новый файл. Пишет только в `hub/docs/out/`, имя `ГГГГ-ММ-ДД_имя.расширение`, существующее не перезаписывает.

- **По шаблону:** `python tools/generator.py fill шаблон данные.json --out … --strict`.
  `{{ключ}}` — значение; строка таблицы с `{{rows:список}}` повторяется для каждого элемента списка.
  Данные готовит из источника (выгрузка, письмо, слова человека) в JSON и **показывает человеку, откуда взято каждое значение**.
  Нет значения — не сочиняет: метка остаётся, код возврата 2, вопрос человеку.
- **Точечная правка раздела:** `python tools/generator.py update-section док.docx --section "…" --text-file правка.md --out …`.
  Меняются только абзацы названного раздела; таблицы раздела и весь остальной документ остаются побайтно прежними.
  Название раздела должно находиться ровно один раз.
- **Ячейки Excel:** `python tools/generator.py set-cells книга.xlsx --sheet "…" --cells '{"B2": 15}' --out …`. Формулы остаются формулами.
- Отдаёт дальше: путь к новому файлу, путь к исходнику, **список разделов, которые разрешено было менять**.

Генератор не объявляет работу проверенной — это делает только Валидатор.

## Роль 3. Валидатор целостности

Независимая проверка. Получает только файлы «до», «после», источники данных и список разрешённых разделов.
Не исправляет сам: находит — возвращает Генератору или человеку.

**Проверка 1. Изменено только разрешённое.**
`python tools/integrity_diff.py до после --allow "раздел" --save` → «Без изменений: N разд.», `OK изменён: …`,
`НАРУШЕНИЕ изменён: …`. Код 1 = целостность нарушена. Строгий режим ловит и оформление; `--text` — только содержание
(использовать, если человек прямо разрешил менять оформление). «ВНИМАНИЕ: разрешённый раздел не изменился» — правка не применилась.

**Проверка 2. Не осталось меток.** В готовом файле нет `{{…}}` (`python tools/guard.py check файл`).

**Проверка 3. Числа совпадают с источником** (приёмы навыка `validate-data`):
- `python tools/numcheck.py готовый_файл источник1 источник2` — каждое число документа должно находиться в источниках;
- ключевые итоги пересчитать самому вторым способом: «выполнено N из M» — посчитать строки выгрузки; «итого» — сложить слагаемые
  (итог в выгрузке может быть формулой — не верить на слово);
- промежуточные итоги в сумме дают общий; выборочно сверить 2–3 строки таблицы с выгрузкой целиком (не только числа — и статус, и срок);
- порядок величин: тысячи не превратились в миллионы, проценты — в доли;
- красные флаги: слишком круглые числа, 0 % и 100 %, одинаковые значения подряд, дата вне периода отчёта.

**Вердикт — один из трёх:**
- `ПРОВЕРКА ПРОЙДЕНА` — можно показывать и сохранять версию;
- `ПРОЙДЕНА С ОГОВОРКАМИ` — перечислить оговорки (например, «число 650 — расчётное, пересчитано вручную: 120+300+80+150»);
- `НЕ ПРОЙДЕНА` — перечислить задетые разделы / расхождения; версия не сохраняется, файл человеку как готовый не выдаётся.

После вердикта: `python tools/handoff.py stage заявка --set проверено --check ok|fail`.

## Роль 4. Версионер

Задача: хранить версии и объяснять разницу человеческим языком.

- `python tools/versions.py add файл --id документ --type тип --note "что изменено"` — только после вердикта Валидатора
  «пройдена» (или «с оговорками», если человек согласился с оговорками). Тот же файл второй раз версией не станет.
- `python tools/versions.py list` — индекс; `diff id [a b]` — что изменилось по разделам.
- `python tools/version_report.py id [a b]` — локальная HTML-страница сравнения (открывается с диска).
- `python tools/registry.py export` — обновить реестр `hub/docs/registry.md` и записи для страницы «Документы».
- **Действующая версия.** Версионер никогда не назначает её сам. Он сообщает: «сохранена v3; действующая сейчас — v2;
  сделать v3 действующей?» Команда `python tools/versions.py current id N --by "кто, где, когда"` — только после явного решения человека.
- Ответ на «что изменилось»: по разделам, словами («в разделе 3 срок сокращён с 5 до 3 рабочих дней; добавлено правило
  отсчёта срока»), затем — сколько разделов без изменений.

## Порядок работы по заявке

1. Прочитать заявку. Есть `[РЕШИТЬ]` без ответа или не хватает файла — спросить человека, заявку не трогать.
2. Парсер → Генератор → `handoff.py stage … --set собрано`.
3. Валидатор (в Claude Code — отдельным субагентом `doc-validator`) → `stage … --set проверено --check ok|fail`.
4. `check: ok` → Версионер: `versions.py add` → `stage … --set версия --doc id --version N`.
   `check: fail` → версию не создавать; `stage … --set отклонено`, в результате — что задето.
5. `handoff.py done заявка --result-file …` — результат: Файл / Парсер / Генератор / Отчёт валидатора (как есть) /
   Версии / Вопросы к человеку. Затем `registry.py export` и строка в журнал.
6. Ответ человеку: `ЗАДАЧА → КАК РАБОТАЛ → РЕЗУЛЬТАТ → ЧТО ОСТАЁТСЯ ЧЕЛОВЕКУ` (утвердить документ; решить, какая версия действующая).

## Если скриптов нет (Cowork, чат)

Честно сокращённый режим:
- **Простые документы** собирать средствами среды (встроенные навыки `docx`/`xlsx`, если включены): короткий документ по
  шаблону из данных, таблица, формула Excel с объяснением. Проверка — глазами по списку: все разделы шаблона на месте,
  ни одного придуманного значения, числа сверены с источником вручную и перечислены.
- **Тяжёлые операции не имитировать:** точечная правка большого документа, проверка целостности по хэшам, версии.
  Вместо этого оформить заявку в `hub/handoff/` по формату протокола (`needs: code`, `stage: принято`), приложить пути
  к файлам и сказать: «это доделает Claude Code на компьютере при следующем запуске; результат появится в заявке и на странице».
- Нельзя писать «целостность проверена», если `integrity_diff.py` не запускался. Можно: «сверено глазами, хэш-проверки не было».

## Ограничения

- Только .docx/.xlsx. Сканы и PDF — не правим.
- Большой документ целиком в ответ не выводится: работаем по разделам, человеку показываем оглавление и изменённый раздел.
- Точечная правка меняет абзацы раздела; правку внутри таблиц Word делает человек или отдельный запрос (и Валидатор её увидит).
- Документы с персональными и закрытыми сведениями в учебном стенде не обрабатываются.
