# Уровни: от промпта до инженерного конвейера

На каждом уровне — одно задание на 15–30 минут. Формат ответа агента на всех уровнях:
`ЗАДАЧА → КАК РАБОТАЛ → РЕЗУЛЬТАТ → ЧТО ОСТАЁТСЯ ЧЕЛОВЕКУ`, и строка в журнал `hub/journal.md`
(`| дата | агент | что сделано | агент, мин | вручную, мин | где запущен |`; в чате журнал ведите сами).

На всех уровнях человеку остаётся: **утвердить итоговый документ и решить, какая версия действующая**.

Учебные файлы появляются в `hub/` после `python tools/demo.py load` (или фразы «загрузи учебный набор»).

---

## L1 «Промпт»: документ по фиксированному шаблону

**Что добавляется.** Инструкция, которая заставляет модель буквально следовать шаблону и ничего не выдумывать.

**Где работает.** Чат claude.ai (Проект), Cowork, Claude Code.

**Задание (15 мин).** Создайте Проект по [SETUP.md, вариант В](SETUP.md), вставьте инструкцию из
[prompts/L1_инструкция_проекта.md](prompts/L1_инструкция_проекта.md). Дайте шаблон отчёта (разделы «Итоги», «Задачи»,
«Бюджет», «Риски») и данные из `demo/hub/docs/in/demo_данные_отчёта.json`, но **удалите из данных поле «период»**.
Попросите собрать отчёт.

**Уровень взят, если:** в ответе те же разделы в том же порядке; все числа из данных; вместо периода стоит
`[НЕТ ДАННЫХ: период]`, и этот пропуск назван в конце списком — а не придуман «сентябрь».

**Типичная ошибка.** Просить «сделай красиво»: модель меняет структуру и дописывает «выводы», которых нет в данных.

**Что остаётся человеку.** Проверить числа по источнику, дать недостающее, утвердить.

## L2 «Правка с доказательством»: один раздел + отчёт целостности

**Что добавляется.** Точечная правка раздела большого документа и независимое сравнение «до/после» по разделам.

**Где работает.** Claude Code. В Cowork — оформляется заявка `needs: code`; в чате — только на вставленном фрагменте, без доказательства.

**Задание (20 мин).** В Claude Code: «В `demo_регламент.docx` замени раздел "Сроки согласования" на текст из
`demo_правка_сроков.md`, остальное не трогай, покажи отчёт проверки». Затем: «Проверь `demo_регламент_правка_от_коллеги.docx`:
коллега должен был менять только раздел про сроки».

**Уровень взят, если:** в первом случае отчёт говорит «OK изменён: 3. Сроки согласования», «Без изменений: 17 разд.»,
«целостность соблюдена»; во втором — два «НАРУШЕНИЕ» (разделы 2.2 и 7) и вердикт «НЕ ПРОЙДЕНА». Исходник не изменился.

**Типичная ошибка.** Попросить модель «переписать документ с правкой»: она перепечатает всё и незаметно изменит формулировки
в других местах. Правка должна идти скриптом по одному разделу, а проверка — отдельно от правки.

**Что остаётся человеку.** Решить, что делать с правкой коллеги: вернуть или принять осознанно.

## L3 «Конвейер и версии»: четыре роли, заявки, «что изменилось»

**Что добавляется.** Роли Парсер → Генератор → Валидатор → Версионер как субагенты; хранилище версий; заявки с этапами
`принято → собрано → проверено → версия`; сборка по шаблону с проверкой чисел.

**Где работает.** Claude Code — полностью. Cowork — подаёт заявки и читает реестр.

**Задание (30 мин).** «Обработай заявки» — в учебном наборе их три (отчёт по шаблону, правка сроков, проверка правки коллеги).
Затем: «Что изменилось между версиями регламента?» и «сделай страницу сравнения версий 2 и 3».
В Cowork (по желанию): «оформи заявку: обновить раздел 5 регламента» — и обработайте её в Claude Code.

**Уровень взят, если:** две заявки дошли до этапа «версия», третья — «отклонено» с перечислением задетых разделов;
`python tools/versions.py list` показывает v3 регламента и «действующая: не назначена»; агент **спросил** вас о действующей
версии, а не назначил сам; открывается HTML-отчёт сравнения; в журнале три строки.

**Типичная ошибка.** Дать Валидатору пересказ Генератора («я изменил только раздел 3») — он поверит. Валидатор получает
только файлы и список разрешённых разделов.

**Что остаётся человеку.** Утвердить документы; назвать действующую версию: «действующая версия регламента — третья».

## L4 «Живёт сам»: рутины, Telegram-бот, страница с хранилищем

**Что добавляется.**
- Рутины: набор **минимум** — `docs-handoff` (заявки каждые 2 часа); набор **стандарт** — плюс `docs-weekly`
  (недельный отчёт по версиям) и `docs-tg-pull` (если подключён бот).
- Telegram-бот: переслали боту задачу или файл → заявка; в ответ — «готово, проверка пройдена / не пройдена, версия N».
- Страница «Документы» с хранилищем: реестр, отчёты проверки, версии, выбор действующей версии, новая заявка.

**Где работает.** Claude Code — всё. Cowork — страница и рутина сверки; бота и обработки тяжёлых заявок нет.

**Задание (30 мин).** (1) «Опубликуй страницу документов» → создайте на ней заявку и выберите действующую версию → «сверь
страницу документов». (2) «Поставь на расписание набор минимум». (3) По желанию — подключите бота по [SETUP.md](SETUP.md)
и перешлите ему задачу.

**Уровень взят, если:** заявка со страницы появилась в `hub/handoff/`; ваш выбор версии записан в хранилище с пометкой, кто
и где решил (`versions.py list` показывает `*`); в `hub/routines.md` есть строка рутины; бот (если подключали) ответил статусом без файла.

**Типичная ошибка.** Ждать, что страница «сама» обновится: страница — отражение папки, данные сходятся при сверке
(по кнопке, по фразе или в рутине). Вторая ошибка — разрешить рутине отправлять файлы: рутины шлют только статус.

**Что остаётся человеку.** Давать «да» на публикацию, каждую рутину и каждый отправляемый файл; выбирать действующую версию.

## L5 «Инженерный»: поиск по структуре, эвалы, хук, свой шаблон

**Что добавляется.**
- **Типизированный поиск по структуре документов:** `python tools/doc_search.py "срочные" --type регламент` — ищет по
  разделам версий, по умолчанию только в действующей (или последней) версии, отвечает «документ · версия · раздел · строка».
- **Эвалы целостности + рубрика:** `python tools/evals.py` — 11 случаев (лишняя правка, подмена ячейки, удалённый раздел,
  неприменившаяся правка, выдуманное число…). Рубрика вердикта — три уровня из `playbooks/05_docs.md`.
- **Независимый проверяющий субагент** `doc-validator`: проверьте, что он ловит ошибку, которую вы внесли руками.
- **Хук и разрешения Claude Code:** проверка перед записью в `hub/docs/out` и защита хранилища (см. ниже).
- **Свой шаблон и свой навык** через `skill-creator`.
- **MCP (описание):** хранилище документов организации можно подключить как MCP-сервер, чтобы Парсер читал файлы оттуда,
  а не из папки; в кейсе это не настроено — правила те же: источник не меняем, результат — новый файл.
- **Метрики в журнале:** доля заявок, прошедших проверку с первого раза; минуты «агент / вручную» по `hub/journal.md`.
- **Встраивание в кейс 6:** заявки `to: docs` из общей доски ассистента проходят этот конвейер.

**Где работает.** Claude Code.

**Задание (30 мин, выберите два пункта).**
1. *Хук.* Добавьте в `.claude/settings.json`:
   ```json
   "hooks": {"PreToolUse": [{"matcher": "Write|Edit", "hooks": [{"type": "command", "command": "python tools/guard.py hook"}]}]}
   ```
   Попросите агента «перезапиши файл в hub/docs/out» — запись должна быть заблокирована с объяснением.
   Честное ограничение: хук видит запись инструментами Write/Edit, но не запись из скриптов через Bash — поэтому перед
   выдачей файла Валидатор всё равно запускает `python tools/guard.py check файл`.
2. *Свой эвал.* Допишите в `tools/evals.py` случай «добавлен новый раздел без разрешения» и добейтесь «прошло 12 из 12».
3. *Свой шаблон.* Сделайте шаблон своего документа с метками `{{ключ}}` и `{{rows:список}}`, положите в `hub/docs/templates/`,
   соберите документ с `--strict`, затем оформите правила его заполнения навыком: «создай навык для моего шаблона» (`skill-creator`).
4. *Поиск.* Сделайте v3 действующей и убедитесь, что `python tools/doc_search.py "рабочих дня"` отвечает из v3, а с `--all-versions` — из всех трёх.
5. *Кейс 6.* Скопируйте свой шаблон в `hub/docs/templates/` ассистента кейса 6 и подайте заявку с его доски.

**Уровень взят, если:** выбранные два пункта работают и вы можете показать вывод (блокировка хуком, «12 из 12»,
собранный по вашему шаблону документ без меток, ответ поиска с версией и разделом).

**Типичная ошибка.** Считать, что хук заменяет проверку. Хук — страховка от случайной перезаписи; доказательство целостности —
это отчёт `integrity_diff.py`. Вторая ошибка — эвалы только на «хорошие» случаи: ценность в случаях, где проверка обязана упасть.

**Что остаётся человеку.** Решать, какие проверки обязательны для его документов; утверждать шаблон; по-прежнему —
утверждать документы и выбирать действующую версию.
