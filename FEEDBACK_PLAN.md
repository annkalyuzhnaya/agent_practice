# Правки по итогам пробного прохождения — предложение

Черновик для обсуждения. Источники: устный отзыв по Hermes и общему подходу и файл «заметки по агентному ИИ»
(общие пункты, кейсы 1, 4, 5, 6). Повторы из двух источников сведены вместе; в скобках указаны номера пунктов
заметок. Файлы практики пока не правились — здесь только план. Внизу — порядок работ.

## Коротко

1. **Главное.** Инструкции разжёваны так, что их незачем проходить, а выбор слишком большой: людям легко
   потеряться, а ведущим — помогать. Нужно сократить и упростить: показать принцип, дать короткий путь, в конце
   показать фишки.
2. **Инструкции.** Одна HTML-страница-оглавление. В кейсе один способ установки, общее вынесено в отдельный блок,
   подробности свёрнуты.
3. **Ошибки, которые точно надо исправить.**
   - Публикацию страницы блокирует автоматический режим Claude Code (кейсы 4 и 5).
   - Навыки Hermes не находятся, если папка лежит внутри `agent_practice`.
   - В README мира Claude «шесть кейсов» и упоминание Hermes.
   - Таблица Cowork/Code про Telegram читается как противоречие.
4. **Нужны твои решения** (п. 0.1, 0.4, 3.2): сколько треков оставить на занятии, будут ли уровни, учебный ключ
   API и как раздавать токен Telegram.

## 0. Формат занятия

### 0.1. Сократить выбор: 2 трека вместо 5 треков и 6+ кейсов (заметки 2, 5, 15)

**Проблема.** Каждый делает своё, людей много. Помощникам (6–7 человек) трудно сориентироваться, кто где застрял.
Есть риск, что участники почувствуют себя брошенными один на один с кейсом.

**Предложение.** На занятии два трека, остальное — «после занятия»:

| Трек занятия | Что делают все | По желанию после |
|---|---|---|
| **Claude** | кейс 1 «Обозреватель» в Claude Code | кейсы 2–5, ассистент (6) |
| **Hermes** | тот же Обозреватель в Hermes | оркестратор, ручная сборка (трек 5) |

Один кейс на трек — значит, ведущий может идти впереди: «делаем вместе, вы повторяете» (заметка 15). Помощники
знают, где именно человек застрял. Обозреватель выбран потому, что он есть в обоих мирах, даёт видимый результат
и на нём лучше всего видны фишки: расписание, Telegram, страница, модели под роли.

**Нужно решение:** какие кейсы оставить в основном пути — Обозреватель, или пусть выбирают из двух-трёх.

### 0.2. Сценарий занятия (заметки 4, 5, 7, 13, 16 и устный отзыв)

1. **Показ до практики** (10 минут, в презентации): как выглядит папка кейса, что такое `CLAUDE.md` / `AGENTS.md`,
   плейбук, `hub/`. Открыть исходные учебные файлы (`demo/`) — с чем работает агент (заметки 7, 16).
2. **Вместе по шагам** (30–40 минут): ведущий на экране, участники повторяют. Где агент думает долго — сказать,
   чем заняться (п. 2.4).
3. **Свободно** (15–20 минут): кто успел — второй кейс или свои данные из домашнего задания (п. 0.3).
4. **Показ соседу** (10 минут): пары показывают друг другу результат. Ведущие проходят по рядам и смотрят
   у каждого — так понятнее, чем общий обход (заметка 5).
5. **Фишки** (15 минут, ведущий): то, что описано в инструкциях, но вряд ли кто-то освоит сам (заметка 13):
   - Telegram-бот: ТОП-3 на телефон, ссылки боту;
   - cron / рутины: агент живёт по расписанию;
   - Tavily — усиленный поиск;
   - Obsidian — база знаний;
   - коннектор Gmail — для «Входящих» (п. 2.6);
   - в Hermes: модель под роль с проверкой приёмкой; проверяющий на другой модели; оркестратор «мой день» над
     двумя ассистентами.

Финальная программа с таймингами — вне репозитория. Её надо сверить с этим списком (заметка 4).

**Кто помогает застрявшим.** Если трек один, у каждого помощника свой ряд и один и тот же сценарий. Запасной
путь для совсем застрявшего — готовый результат в `demo/пример_результата/`: человек смотрит на него и идёт дальше
со всеми. Об этом пути стоит сказать участникам заранее.

### 0.3. Данные из домашнего задания (заметка 3)

**Проблема.** Непонятно, в каком формате участники принесут материалы и куда их класть.

**Предложение.** В каждом кейсе раздел «Что принести» (одна таблица): формат (`.md`, `.txt`, `.docx`, `.pdf`,
выгрузка писем `.eml` / текст), примерный объём, куда положить (`hub/inbox/`, `hub/kb/…`) и одна фраза агенту.
До занятия разослать участникам ту же таблицу.

**Нужно решение:** какое домашнее задание было озвучено, чтобы таблица совпала с ним.

### 0.4. Уровни L1–L5 (заметка 6)

**Проблема.** Деление на уровни путает.

**Предложение.** На занятии уровни не упоминать. `LEVELS.md` оставить как «куда расти после занятия»
и не ссылаться на него в основном пути.

## 1. Инструкции: одна страница-оглавление, один способ, общее — отдельно

### 1.1. Сейчас

- `.md` участникам неудобно читать (заметка 1).
- `START.html` в каждом кейсе — 540–770 строк, шесть-семь одинаковых разделов. В шести кейсах мира Claude
  разделы «Установка», «Подключения», «Если что-то не так» почти совпадают слово в слово (заметка 12).
- В кейсе по три способа установки (Claude Code / Cowork / чат) (заметка 11).
- Готовые длинные запросы («Настрой себя полностью, за один разговор…») делают всё за участника — проходить
  по инструкции незачем (устный отзыв).

### 1.2. Предложение

1. **Одна входная страница** `START.html` в корне (заметки 1, 10). Слева — оглавление: «Как устроена практика»,
   «Установка», кейсы, «Фишки», «Если что-то не так». Справа — выбранная страница. Переключение без поиска файлов.
   `.md` остаются для Claude и авторов; участнику достаточно HTML.
2. **Общие блоки — по одному на мир** (заметка 12): установка, подключения (Telegram, cron/рутины, страница,
   Tavily), «если что-то не так». Кейс ссылается на них одной строкой.
3. **Страница кейса — три части:**

   | Часть | Объём | Что в ней |
   |---|---|---|
   | **Принцип** | 1 экран | что делает агент, схема, что лежит в папке, что такое `hub/` (заметка «кейс 1, п. 7») |
   | **Быстрый старт** | 3–5 шагов | открыть папку в Claude Code → «настрой» → первый результат. Один способ (заметка 11); участник говорит с агентом сам, без готовых запросов на всё сразу |
   | **Что дальше** | список | фишки кейса; как работать со своими данными (п. 2.7); расписание и как его менять (п. 2.3) |

4. **Остальное — свёрнуто** (`<details>`, заметка «кейс 1, п. 6»): Cowork, чат claude.ai, ручная установка,
   длинные готовые запросы. Блок развернёт тот, кому интересно; по умолчанию его не видно. В конце быстрого старта
   строка: «Застряли или нужен другой способ — спросите Claude в папке кейса».

**Объём.** Большой: одна входная страница, два общих блока и пересборка восьми страниц кейсов. Предлагаю сначала
сделать по новому образцу одну страницу (Обозреватель в Claude), согласовать её и потом перенести на остальные.

## 2. Мир Claude

### 2.1. README мира Claude: «шесть кейсов» и упоминание Hermes (заметки 8, 9)

**Где.** `1_claude/README.md`:

- первая строка — «Шесть самостоятельных кейсов», хотя на занятии говорим о пяти тематических и ассистенте;
- строка «Мир Hermes (треки 3–5) — в `../2_hermes/`» сбивает участника трека Claude.

**Предложение.**

- Переписать так: «Пять тематических агентов (выбираете один) и личный ассистент, который объединяет все пять».
- Ссылку на Hermes убрать: она есть в корневом README.

**Объём.** Маленький.

### 2.2. Cowork или Claude Code, зачем проект (заметки 14, «кейс 1, п. 1»)

**Проблема.**

- Непонятно, чем отличаются две версии.
- В START.html сказано «Режим Cowork — без Telegram-бота». Это читается так, будто в версии Code бот есть сразу,
  а его нет: бот подключается отдельно.

**Предложение.** В блок «Принцип» — короткая таблица из трёх строк:

| Среда | Что это | Что умеет |
|---|---|---|
| **Claude Code** | агент работает с папкой на вашем компьютере | всё: скрипты, субагенты, свой бот (подключается отдельно, по желанию) |
| **Cowork** | агент в приложении, правила приходят плагином | без скриптов и бота, по очереди вместо субагентов |
| **Проект в чате** | только инструкция | без памяти в файлах; уровень «попробовать идею» |

Плюс одна фраза о том, зачем нужен проект: проект — это папка с правилами (`CLAUDE.md`), которые агент читает
в начале каждого разговора. На занятии используем только Claude Code. Cowork и чат — свёрнутым блоком.

### 2.3. Как часто живёт агент и как это поменять («кейс 1, п. 3»)

**Предложение.**

- В конце настройки агент сам пишет итог: какие рутины созданы, когда они срабатывают, что делать по запросу.
  Добавить фразу: «поменять — скажите „измени расписание“ или „выключи рутины“».
- Правка в плейбуке настройки (`playbooks/02_setup.md` / `04_routines.md`) каждого кейса и пересборка.

### 2.4. Агент думает 5 минут — что делать участнику («кейс 1, п. 4»)

**Проблема.** Первый выпуск идёт около 5 минут. Агент начал выпуск ещё до шага настройки.

**Предложение.**

1. В быстром старте прямо написать: «Первый выпуск идёт 3–5 минут. Пока ждёте — откройте `hub/` и посмотрите, что
   агент записал в профиль». Или: «откройте второй кейс в новом окне».
2. Проверить по плейбуку, почему выпуск стартовал до настройки. По тексту шагов пробный выпуск — шаг 3, после
   профиля. Нужно воспроизвести: возможно, агент принял первое сообщение за запрос выпуска.

### 2.5. Токен Telegram через Блокнот («кейс 1, п. 5»)

**Почему так сейчас.** Токен не пишем в чат: всё, что попадает в чат, уходит в историю разговора. Поэтому агент
создаёт файл, а человек вписывает токен сам. Плюс правило `deny: Read(./hub/.secrets/**)` в `.claude/settings.json`.

**Варианты.**

- **А (предлагаю).** Оставить принцип, убрать ручную работу: агент сам открывает файл в Блокноте
  (`notepad hub\.secrets\telegram.json`). Человеку остаётся вставить токен и сохранить. Шаг занимает 30 секунд.
- **Б.** Разрешить вставить токен в чат. Агент записывает его в файл. Риск: токен остаётся в истории разговора.
  На занятии можно, если бот учебный и после занятия его удаляют.

**Нужно решение:** А или Б.

### 2.6. Публикацию страницы блокирует автоматический режим (кейсы 4 и 5)

**Что видели.**

- Кейс 4: «Обязательная часть настройки готова, но опубликовать страницу „Входящие“ не получилось: публикацию
  заблокировал автоматический режим разрешений Claude Code».
- Кейс 5: то же.

**Причина.** Публикация страницы — действие наружу. Режим auto в Claude Code такие действия без явного
подтверждения не пропускает. Разрешения в `.claude/settings.json` кейсов покрывают только скрипты `tools/` и
веб-поиск.

**Предложение.**

1. В плейбуке страницы (`03_artifact.md`) сделать публикацию отдельным шагом с вопросом: «Публикую страницу —
   да?». Если инструмент всё равно заблокирован, агент пишет точную инструкцию: «нажмите Shift+Tab, чтобы
   переключить режим на обычный, и скажите „опубликуй страницу“».
2. Проверить, можно ли разрешить публикацию заранее строкой в `permissions.allow` настроек кейса. Если да —
   добавить её в сборку (`tools/build.py`), а в START.html написать, что публикация приватная до вашего «поделиться».
3. В быстром старте сказать заранее: «Claude Code может спросить разрешение на публикацию страницы — разрешите».

Пока это не исправлено, сказать участникам на занятии.

### 2.7. Кейс 4 «Входящие»: Gmail в фишки; чем отличается от Библиотекаря (заметки «почта, п. 1, 3»)

**Предложение.**

- Коннектор Gmail (уже описан в `04_inbox/SETUP.md`) вынести в фишки и показать на финале.
- В блок «Принцип» — короткое сравнение:

  | | База знаний | Входящие |
  |---|---|---|
  | Отвечает на вопрос | «что сказано в моих материалах?» | «что с этим письмом делать?» |
  | Результат | ответ со ссылкой на источник | категория и срок, черновик ответа, задача в `hub/tasks.md` |

  Без коннектора разница остаётся: Входящие выдают черновики и задачи, а не ответы по базе.

### 2.8. Кейс 5 «Документ-инженер»: как работать дальше со своими файлами («документы, п. 1»)

**Предложение.** Раздел «На своих документах». Тезисы:

- проект один, новый проект или чат под каждый файл не нужен;
- шаблоны класть в `hub/templates/`, исходники — в `hub/inbox/`;
- фразы: «сделай по шаблону X из файла Y», «поправь пункт 3 в Z»;
- результат — в `hub/out/` с версией.

Точные имена папок сверить с плейбуком кейса.

### 2.9. Ассистент: работает ли без кейсов 1–5 и зачем тогда кейсы (заметки «ассистент, п. 1, 2»)

**Предложение.** В начало README и START.html ассистента два абзаца:

- **Работает сам по себе.** Все пять ролей уже внутри, проходить кейсы 1–5 заранее не нужно.
- **Зачем тогда отдельные кейсы.** На одном агенте проще понять принцип и настроить его под себя. Ассистент — это
  те же пять ролей и сверху «Мой день». Ему нужно больше настройки и больше токенов.

Поэтому на занятии — один кейс, ассистент — после.

### 2.10. Расход токенов («кейс 1, п. 2»)

**Предложение.** В каждом кейсе одна строка: сколько примерно стоит первая настройка и один прогон, и как
экономить (учебный набор вместо живого поиска, меньше тем, рутины реже). Цифры снять на пробном прогоне.

## 3. Мир Hermes

### 3.1. «Навыки не находятся: ближайший `.git` — это `agent_practice/`»

**Что произошло.** Claude при установке спросил: «Hermes ищет навыки проекта в ближайшей папке с `.git`. Для
`01_digest` это `agent_practice/`, а там навыков нет. Как подключить `digest` и `digest-setup`?»

**Причина.** Папка кейса открыта прямо внутри склонированного репозитория.

- В запросе на установку (`2_hermes/01_digest/START.html`, раздел 2, пункт 3) стоит «выполни `git init` (**если
  она ещё не проект git**)». Внутри `agent_practice` git отвечает «проект», поэтому Claude `git init` не делает
  и упирается в чужой корень.
- Шаблон флота оркестратора сам указывает путь *внутри* репозитория: `D:/Work/agent_practice/2_hermes/01_digest`.
  Он прописан в `orchestrator/presets/hub/fleet.json`, `playbooks/20_fleet.md` и `playbooks/30_remote.md`.

**Предложение.**

1. В запросе на установку сделать копирование первым шагом: «Если эта папка внутри другого проекта git — спроси,
   куда скопировать (по умолчанию `%USERPROFILE%\Hermes\01_digest`), скопируй и работай в копии». Условие для
   `git init` поменять на «если в **самой** этой папке нет `.git`».
2. Добавить эту ошибку дословно в «Если что-то не так».
3. В шаблонах флота поменять путь на папку вне репозитория.
4. Запасной путь: `hermes config set skills.external_dirs '[".../01_digest/.hermes/skills"]'` — работает без git,
   но навыки становятся видны во всех папках.

**Объём.** Маленький.

### 3.2. Ключ API — дать прямо в инструкции

**Ограничение.** Репозиторий **публичный**. Ключ в git считается утёкшим: боты находят такие ключи за минуты.
Поэтому ключ — только вне репозитория.

**Предложение.**

1. Один учебный ключ у агрегатора с жёстким лимитом и сроком на день занятия. После занятия ключ отозвать.
2. Раздать в чате группы или на слайде.
3. В инструкции блок «Что выдаст ведущий»: адрес, модель, ключ — «в чате группы». Адрес и модель заранее вписать
   в запрос на установку, чтобы их не спрашивали.
4. Раздел «как выбрать провайдера и получить свой ключ» — свёрнутым блоком «после занятия».

**Нужно решение:** провайдер и лимит.

### 3.3. Установка Hermes — одна инструкция вместо трёх

**Сейчас установка описана в трёх местах, и везде по-разному:**

- `01_digest/START.html` — через Claude готовым запросом;
- `01_digest/SETUP.md` — вручную, только Windows;
- `manual/MANUAL.md` — вручную, Windows и macOS, подробно;
- в `orchestrator/` установки нет вовсе.

**Предложение.** Общий блок «Установка Hermes» (часть п. 1.2):

- **основной путь** — руками в окне команд;
- **запасной** — короткий запрос к Claude;
- общая часть — ключ, веб-панель, шлюз, типовые ошибки.

Кейсы, `manual` и `orchestrator` на него ссылаются. Своим у кейса остаётся один шаг — подключить папку
(копия + `git init` + `hermes skills trust`).

### 3.4. В оркестраторе нет HTML-инструкции

**Предложение.** `orchestrator/START.html` в новом формате (п. 1.2):

- принцип со схемой «Claude-дирижёр → флот Hermes → один план»;
- быстрый старт в 4 шага;
- фишки.

Её всё равно писать с нуля, поэтому она может стать первой страницей нового образца для Hermes.

### 3.5. Оркестратор — непонятно, кем рулит, если есть только Обозреватель

**Предложение.**

1. Основной сценарий — флот из двух ассистентов, которые уже есть:
   - Обозреватель (трек 3) — даёт ТОП-3;
   - универсальный помощник трека 5 (`manual/templates`) — даёт задачи и заметки.

   «Мой день» сводит их в один план. В шаблон `fleet.json` положить обе записи.
2. В быстром старте шаг: «Нет второго ассистента — попросите Claude собрать его по `BUILD.md`».
3. Удалённый флот показывать на той же папке помощника на втором компьютере или в WSL.

**Объём.** Маленький.

## 4. Используется ли папка `skills_pack/`

**Ответ.** Да, но только при сборке — участнику она не нужна.

1. `skills_pack/skills/` — единый источник сторонних навыков (internal-comms, build-dashboard, tavily-*,
   skill-creator и др.).
2. `python skills_pack/sync.py` раскладывает их по кейсам в `<кейс>/pack/` по `skills_pack/manifest.json`.
3. `python tools/build.py` в кейсе копирует их в `.claude/skills/`, плагин Cowork или `.hermes/skills/`.

**Предложение.** В корневом README перенести `skills_pack/` в раздел «Для авторов практики» с пометкой
«служебное, участнику не нужно». Переносить папку не нужно: тогда пришлось бы менять пути в скриптах.
