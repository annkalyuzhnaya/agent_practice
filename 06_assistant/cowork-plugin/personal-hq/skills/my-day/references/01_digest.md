# Плейбук №1. Обозреватель — дайджест по темам владельца

**Роль.** Персональный аналитик: вместо владельца просматривает источники и выдаёт короткую выжимку с приоритетами.

## Вход
- `hub/profile.md` — темы-приоритеты, «что не интересно», список источников.
- `hub/digest/seen.md` — ссылки, которые уже показывал.
- Опционально: тема или период в запросе («дайджест за неделю по …»). Если человек вставил публикации текстом — работай с ними без поиска.

## Шаги
1. **План.** По каждой теме профиля сформулируй 1–2 поисковых запроса; добавь обход источников из профиля. Период по умолчанию — 7 дней. При первом запуске (`seen.md` пуст) — 30 дней.
2. **Сбор.** Веб-поиск и чтение страниц. Если в среде есть программа `tvly` (навыки `tavily-search`, `tavily-extract`) — ищи и читай страницы ею: результаты точнее и с датами; для большой темы «разберись подробно» — `tavily-research`. Нет её — встроенный веб-поиск, результат тот же по форме. В запрос идут только темы профиля, ничего личного с шины. Веб-поиска нет вовсе — скажи об этом и работай с публикациями, которые человек вставил текстом. Только открытые источники; paywall и недоступные сайты пропускай без повторных попыток. Страница не открылась — позицию по одной поисковой выдаче не включай: перечисли такие ссылки в блоке «Не удалось открыть» и в `seen.md` не записывай. Ссылайся на первоисточник; если доступен только пересказ — так и пометь.
3. **Дедупликация.** Убери всё, что есть в `seen.md`, и повторы одной новости из разных источников (оставь первоисточник).
4. **Рубрика релевантности 1–5** к профилю: 5 — прямо влияет на задачи владельца в ближайший месяц; 3 — полезный контекст; 1 — общий фон. Каждую оценку объясни одной фразой. Оценки 1–2 в дайджест не разворачивай — только строкой в «Пропущено».
5. **Дайджест.** Отсортируй по убыванию оценки, не больше 10 позиций.
6. **Самопроверка.** У каждой позиции есть рабочая ссылка и дата публикации; дата попадает в период; выводы следуют из текста источника, а не из заголовка. Публикацию старше периода с оценкой 5 можно включить — в отдельную рубрику «Вне периода, но важно», не больше двух.

## Выход
Файл `hub/digest/ГГГГ-ММ-ДД.md`:

```
## ТОП-3 — на что обратить внимание
## Публикации
### [оценка 5] Заголовок — источник, дата, ссылка
- TL;DR: одна фраза
- Почему важно для меня: …
- Что сделать: одно конкретное действие
## Вне периода, но важно (если есть)
## Пропущено (низкая релевантность): одной строкой каждая
## Не удалось открыть: ссылки
## Что остаётся человеку: решить, что из ТОП-3 берём в работу
```

Одностраничную HTML-карточку дайджеста (шапка с датой, карточки с бейджем оценки, блок ТОП-3) делай только по просьбе человека — когда дайджест нужно переслать. Выпуск для коллег (вступление, три главных новости, что это значит для нас) оформляй приёмами навыка `internal-comms`; страницу — приёмами `build-dashboard` (один файл в `hub/docs/out/`). Рассылает человек.

## Связи с другими агентами
- Все показанные ссылки (включая «Пропущено») допиши в `hub/digest/seen.md` (`- дата | ссылка | заголовок`).
- Позиции с оценкой 4–5 должны попасть в базу знаний. В сценарии «Мой день» заметки создаёт Библиотекарь на своём шаге — сам их не создавай. При отдельном запуске создай заметки по правилам плейбука №2.
- Если публикация касается контрагента из `hub/calendar.md` или задачи из `hub/tasks.md` — явно отметь это в дайджесте («к встрече с …», «к задаче …»).
- Действие «что сделать» с оценкой 5 предложи как задачу — допиши в `hub/tasks.md` со статусом `предложено`.
