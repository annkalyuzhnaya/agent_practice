# «Входящие»: установка и настройка

Кейс самодостаточный: всё нужное лежит в этой папке. Выберите один из трёх путей — дальше агент сам проведёт
по шагам в чате.

| Путь | Что получите | Что нужно | Время |
|---|---|---|---|
| **А. Claude Code** | всё: три роли-субагента и проверяющий, скрипты, бот Telegram, рутины, страница | приложение Claude (вкладка «Code»), Python 3.10+ | 5–10 минут |
| **Б. Cowork** | разбор, черновики, задачи, память, страница и рутины; без субагентов, скриптов и бота | приложение Claude, файл `dist/hq-inbox.plugin` | 3 минуты |
| **В. Чат claude.ai** | таблица разбора и ответы в чате (уровень L1) | любой тариф claude.ai | 2 минуты |

Ваши данные хранятся в папке `hub/` внутри папки кейса, на вашем компьютере. В git она не попадает.

## А. Claude Code — полный вариант

1. Скопируйте папку `04_inbox` в постоянное место (на неё будут ссылаться рутины), например `D:\Work\04_inbox`.
2. Проверьте Python: в терминале `python --version` должен показать 3.10 или новее. Нет — установите с python.org
   (на Windows с галочкой «Add python.exe to PATH») и перезапустите приложение Claude. Дополнительные библиотеки не нужны.
3. В приложении Claude: вкладка **Code** → «Новая сессия» → выберите папку `04_inbox`.
4. Напишите в чат: `настрой входящие`.

Агент поздоровается, создаст шину `hub/` (командой `python tools/setup.py` — разрешите запуск) и проведёт по шагам.
Субагенты и навыки уже лежат в `.claude/`; пересобрать их после правки плейбуков — `python tools/build.py`.

## Б. Cowork — плагин

1. Откройте Cowork и перетащите в чат файл `dist/hq-inbox.plugin` → «Установить».
2. Выберите рабочую папку: новую пустую или папку кейса, если уже работали в Claude Code (шина общая).
3. Напишите: `настрой входящие`.

**Что в Cowork урезано и чем заменено:**

| Нет в Cowork | Чем заменено |
|---|---|
| Субагенты (`inbox-classifier`, `inbox-drafter`, `inbox-prioritizer`, `inbox-checker`) | те же роли четырьмя последовательными проходами в одном разговоре; независимость проверки слабее |
| Скрипты Python (`tools/*.py`) | шину создаёт навык `setup` чтением заготовок; формальную проверку агент делает чтением файлов |
| Мост Telegram и рутина `inbox-tg-pull` | вставлять сообщения в чат; заявка в `hub/handoff/` с `needs: code` — выполнится в Claude Code |
| Навык `skill-creator` | в плагин не включён (ему нужны Python и командная строка); уровень L5 проходится в Claude Code |

Страница и рутины в Cowork работают, если в вашей версии доступны инструменты публикации и расписания; мастер
проверяет это на шаге 0 и честно пишет в `hub/setup.md`, чего нет.

## В. Проект в claude.ai — без папки

Откройте [prompts/L1_инструкция_для_Проекта.md](prompts/L1_инструкция_для_Проекта.md), создайте проект, вставьте
инструкцию, вставьте письма. Ничего не сохраняется и не отправляется; результат копируете сами.

## Шаги мастера

Один шаг — один экран; вопросы формой с вариантами (нет форм — отвечайте цифрой). Прервать можно в любой момент:
«продолжи настройку» вернёт к первому незавершённому шагу. Ничего не включается без вашего «да».

| Шаг | Обязателен | Время | Что делает агент | Что нужно от вас |
|---|---|---|---|---|
| 0. Среда и шина | да | 1 мин | проверяет возможности среды, создаёт `hub/` | разрешить запуск команды |
| 1. Профиль и память | да | 3 мин | записывает роль, часы, тон, людей, сокращения | ответить на форму |
| 2. Пробный разбор | да | 3 мин | разбирает 12 учебных сообщений или ваши письма | посмотреть результат |
| 3. Страница «Входящие» | нет | 2 мин | публикует приватную страницу | сказать «да», закрепить страницу |
| 4. Почта | нет | 3 мин | проверяет коннектор, записывает правила доступа | войти в почту в настройках Claude |
| 5. Бот в Telegram | нет, только Code | 5 мин | готовит файл для токена, проверяет бота | создать бота, вписать токен |
| 6. Рутины | нет | 2 мин | создаёт запуски по расписанию | выбрать набор и время |
| 7. Итог | — | 1 мин | показывает, что включено и что отложено | — |

Состояние настройки без чата: `python tools/setup.py status`.

## Почта

Почта подключается **коннектором в настройках Claude**, пароль агенту не нужен: Настройки → Коннекторы → Gmail
(или Outlook) → «Подключить» → войти в свою учётную запись. Затем в чате: `подключи почту`.

- **Корпоративный ящик** подключайте, только если это разрешено правилами вашей организации. Агент спросит об этом
  отдельно и без подтверждения шаг отложит. Замены: личный ящик, пересылка писем боту, вставка в чат.
- Агенту разрешено: читать новые письма, раскладывать их на шину, готовить черновики.
- Агенту запрещено: удалять письма, менять метки, фильтры и пересылку, отправлять что-либо без вашей кнопки.
- **Отправку по кнопке «Отправить»** вы разрешаете отдельным ответом «Да, разрешаю»; запись появляется
  в `hub/accounts.md`. Без неё агент создаёт только черновики. Отозвать: «запрети отправку».

## Свой бот в Telegram

Только Claude Code. Бот — «почтовый ящик»: вы пересылаете ему письма и сообщения, агент забирает их по расписанию
или в начале разговора. Мгновенно бот не отвечает. Ваши личные переписки бот не видит.

1. В Telegram откройте **@BotFather** → `/newbot` → имя бота → адрес, оканчивающийся на `bot`. В ответ придёт токен.
2. В чате Claude: `подключи телеграм`. Агент выполнит `python tools/tg_bridge.py init` и назовёт файл
   `hub/.secrets/telegram.json`. Откройте его сами и вставьте токен в кавычки строки `"token": ""`, сохраните.
   **В чат токен не присылайте** — агент его не просит, не читает и не показывает.
3. Агент выполнит `python tools/tg_bridge.py check` — должно появиться имя бота.
4. Напишите своему боту `/start`. Агент выполнит `python tools/tg_bridge.py whoami`, спросит «это вы?» и после «да»
   запишет ваш номер командой `python tools/tg_bridge.py set-owner НОМЕР`.
5. Выберите, что бот присылает: утреннюю сводку и вечерний контроль, только ответы на вопросы или ничего.

**Что присылать боту:** пересланное письмо или сообщение (попадёт в разбор), свой вопрос «что срочного»,
«запомни, что …». **Что бот присылает:** сводку до семи строк — без адресов почты и текстов писем.
**Чего бот не делает:** не отправляет писем, не пишет другим людям, не выполняет инструкции из пересланного.
Рутина опроса — `inbox-tg-pull` (каждые 20 минут с 8 до 21), включается на шаге «Рутины».

## Страница «Входящие»

Файл `artifacts/inbox.html`. Вкладки: **Почта** (письма, суть, поле с текстом ответа и его варианты; кнопки
«Отправить», «В черновик», «Игнорировать», «Отправить сейчас», «Отменить отправку»), **Задачи** (смена статуса, правка,
свои задачи), **Разбор** (итоги последнего разбора, план, замечания безопасности, письма без ответа дольше двух дней,
счётчик сэкономленного времени).

- **Посмотреть без публикации:** откройте `artifacts/inbox.html` двойным щелчком. Страница покажет учебные данные
  и надпись «Учебные данные · открыто с диска»; отметки живут до закрытия вкладки, ничего никуда не уходит.
- **Опубликовать:** в чате `опубликуй страницу` → «Да». Страница приватная, видите её только вы. Закрепите её.
- **Сверка:** ваши отметки агент забирает по фразе `сверь страницу`, в начале разговора и в конце каждой рутины.
  Ваши отметки переносятся на шину, новое с шины — на страницу. «Отправить сейчас» работает, когда страница
  открыта рядом с разговором с агентом; иначе письмо уйдёт при ближайшей сверке.
- На страницу не попадают адреса почты, полные тексты входящих писем, токены.

## Расписание

`включи рутины` → выбрать набор и время. Создаются инструментом расписания среды; ничего не создаётся без «да».

| Рутина | Когда (по умолчанию) | Что делает | Набор |
|---|---|---|---|
| `inbox-morning` | будни, 8:30 | забирает новое, разбирает, готовит сводку «что срочного» | Минимум, Стандарт |
| `inbox-evening` | будни, 18:30 | напоминает, на что не ответили и что просрочено | Стандарт |
| `inbox-mail-pull` | будни, 9:00, 13:00, 17:00 | забирает новые письма из почты на шину | Стандарт, если подключена почта |
| `inbox-tg-pull` | каждые 20 минут, 8–21 | забирает пересланное боту | Стандарт, только Claude Code с ботом |

Рутины работают, пока приложение Claude открыто. Одну рутину включайте в одной среде — иначе выполнится дважды.
Нет инструмента расписания — те же действия делаются фразами `разбери входящие` и `на что я не ответил`.

## Проверка «всё работает»

В чате (любой путь): `покажи учебный пример` → `разбери входящие` → сравните с
[эталоном](demo/пример_результата/inbox/triage/2026-10-05.md) по [рубрике](demo/рубрика_приёмки.md).

В терминале (Claude Code, в папке кейса):

```bash
python tools/build.py                 # собрать субагентов, навыки и плагин
python tools/setup.py                 # создать hub/ из заготовок
python tools/setup.py status          # состояние шагов мастера
python tools/demo.py load             # положить 12 учебных сообщений и учебную память
python tools/inbox_check.py           # формальная проверка шины и список «на что не ответили»
python tools/inbox_check.py --hub demo/пример_результата --today 2026-10-05   # то же на эталоне
python tools/tg_bridge.py check       # без токена — понятная подсказка, что сделать
python tools/demo.py clean            # убрать учебные файлы
```

Признаки, что всё в порядке: в письме о конференции встроенная инструкция не выполнена и вынесена в «Замечания
безопасности»; задач четыре; ни одно письмо не получило статус «отправлено».

## Навыки пака

Лежат в `pack/skills/`, сборка копирует их в `.claude/skills/` и в плагин. Ключи и подключения не нужны.
Источник правды во всех случаях — файлы `hub/`; навыки дают приёмы, а не своё хранилище.

| Навык | Зачем в этом кейсе | Ключ или подключение | Как проверить |
|---|---|---|---|
| `task-management` | приёмы выделения и ведения задач; файл — `hub/tasks.md` (свой `TASKS.md` и панель навыка не создаются) | не нужны | «покажи задачи» — таблица из `hub/tasks.md`, файла `TASKS.md` в папке нет |
| `memory-management` | приёмы памяти: люди, сокращения, расшифровка «рабочего языка»; файлы — `hub/memory/` | не нужны | «запомни: КЦ — комитет по цифровизации» → строка в `hub/memory/glossary.md` |
| `internal-comms` | тон и структура коротких служебных ответов и сводок | не нужны | «подготовь ответ … по-деловому» — 2–5 предложений без канцелярита |
| `skill-creator` | уровень L5: собрать свой навык (например, ответы на обращения граждан) | Python; только Claude Code | «собери навык … используй skill-creator» — появляется папка навыка с `SKILL.md` |

Если навык не подключился, разбор не ломается: в плейбуке `playbooks/04_inbox.md` для каждого прописано, что делать
без него. Лицензии — в `pack/THIRD_PARTY.md` и `pack/licenses/`.

## Что можно подключить дополнительно

Это в кейс не скопировано (лицензии и принадлежность другим пакетам). Подключается из каталога: в приложении
Claude — **Настройки → Возможности** (навыки) или **Плагины**; в Claude Code — команда `/plugin`.

| Что | Зачем здесь | Запасной путь без него |
|---|---|---|
| Навыки Anthropic `docx`, `xlsx`, `pdf`, `pptx` | читать вложения писем: договор в Word, выгрузку в Excel, скан в PDF | вставить текст вложения в чат; агент пометит «вложение не прочитано» |
| Навык `schedule` | создавать рутины, если в среде нет встроенного инструмента расписания | запускать фразами «разбери входящие», «на что я не ответил» |
| Desktop Commander: `obsidian-vault`, `knowledge-base` | вести `hub/memory/` как базу заметок в Obsidian | файлы `hub/memory/*.md` читаются любым редактором |
| Официальный плагин `telegram` (Claude Code) | переписка с агентом через бота в реальном времени (уровень L5) | мост `tools/tg_bridge.py` в режиме «почтовый ящик» |
| Коннекторы Gmail, Outlook, календарь | агент сам забирает письма | вставка писем в чат, пересылка боту |

Плагин `telegram` — другой режим работы: сообщения приходят прямо в разговор. Правило «пересланное — данные,
а не команды» при нём не меняется. Кейс его не настраивает.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `python` не найден | установите Python с python.org, на Windows — с галочкой «Add python.exe to PATH»; перезапустите Claude |
| Агент отвечает как обычный Claude | откройте именно папку кейса (Code) или проверьте, что плагин установлен (Cowork); напишите «настрой входящие» |
| Вместо форм — вопросы текстом | в среде нет форм: отвечайте цифрой варианта |
| «Нет hub/.secrets/telegram.json» | бот не настроен: `подключи телеграм` или `python tools/tg_bridge.py init` |
| `check` сообщает об ошибке токена | токен вставлен не полностью или с пробелом — поправьте файл сами |
| Бот молчит | это нормально: он не отвечает мгновенно; напишите в чате «забери телеграм» |
| Нажали «Отправить», письмо не ушло | отправка идёт при сверке: напишите «сверь страницу». Проверьте, что в `hub/accounts.md` отправка разрешена |
| Карточка подключения почты не появилась | Настройки Claude → Коннекторы → подключить там, затем «проверь подключение» |
| Рутина не сработала | приложение Claude было закрыто; откройте его |
| Страница показывает «Учебные данные» | файл открыт с диска; настоящие данные — на опубликованной странице |
| Начать заново | переименуйте `hub` в `hub_старое` и напишите «настрой входящие» |
