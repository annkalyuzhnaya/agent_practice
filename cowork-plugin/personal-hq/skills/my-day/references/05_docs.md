# Плейбук №5. Документ-инженер — Word/Excel без порчи остального

Четыре роли конвейера: **Парсер → Генератор → Валидатор целостности → Версионер**.
Полный конвейер работает в Claude Code (нужны скрипты `tools/`). Только нативные `.docx/.xlsx`.

**Вход:** заявка из `hub/handoff/` (`to: docs`) или прямой запрос человека. Файлы — в `hub/docs/in/`, шаблоны — в `hub/docs/templates/`.

## Если скриптов нет (Cowork, телефон)
- Простая задача (собрать небольшой документ по шаблону, формула, сводная, чистка таблицы) — сделай встроенными средствами работы с docx/xlsx и положи результат в `hub/docs/out/`.
- Большой документ, точечная правка с гарантией целостности, версии, сравнение — **не делай вручную**. Создай заявку в `hub/handoff/` с `to: docs`, `needs: code` и скажи человеку, что её выполнит Claude Code на компьютере.

## Роль 1. Парсер
```
python tools/parser.py <файл>            # оглавление разделов/листов с хэшами
python tools/parser.py <файл> --json     # полная структура
```
Пойми структуру документа до любых изменений. Назови раздел/лист, который предстоит менять, точно как в оглавлении.

## Роль 2. Генератор
- **Документ по шаблону** (данные → готовый файл):
  `python tools/generator.py fill <шаблон> <данные.json> --out hub/docs/out/<имя> --strict`
  Шаблон бери тот, что назван в заявке; не назван и подходит не один — спроси человека. Данные собери из источника (выгрузка xlsx, форма) в JSON сам, ничего не выдумывая. Если человек положил рядом готовый JSON с данными — используй его, но сверь пересекающиеся поля с выгрузкой и перечисли поля, которых в выгрузке нет, как «требуют подтверждения». Скрипт перечислит незаполненные метки — это вопросы к человеку, а не повод придумать значение.
  Метки шаблона: `{{ключ}}`; строка таблицы с `{{rows:имя}}` повторяется по списку.
- **Точечная правка большого документа:**
  `python tools/generator.py update-section <файл.docx> --section "<раздел>" --text-file <текст> --out hub/docs/out/<имя>`
  `python tools/generator.py set-cells <файл.xlsx> --sheet "<лист>" --cells '{"B2": 15}' --out hub/docs/out/<имя>`
- Перед правкой сверь новый текст с формулировкой поручения: всё, что в тексте шире поручения (лишнее предложение, другой срок), внеси, но перечисли в отчёте как `[РЕШИТЬ]` — валидатор целостности этого не ловит.
- Исходный файл никогда не перезаписывай — результат всегда новым файлом в `hub/docs/out/`.
- Нестандартная операция — напиши небольшой скрипт на python-docx/openpyxl по образцу `tools/generator.py`.

## Роль 3. Валидатор целостности
```
python tools/integrity_diff.py <до> <после> --allow "<раздел 1>" --allow "<раздел 2>"
```
Код 0 — изменились только разрешённые разделы. Код 1 — **стоп**: результат не выдавать, разобраться и переделать.
Для сгенерированного по шаблону документа автоматической проверки нет: разбери результат парсером, сверь каждое число с источником данных и перечисли в отчёте, что сверено.

## Роль 4. Версионер
```
python tools/versions.py add <файл> --id <идентификатор> --type <тип> --note "<что изменилось>"
python tools/versions.py diff <идентификатор>        # что изменилось между версиями
python tools/versions.py list
python tools/kb_index.py build                       # новые версии попадают в поиск базы знаний
```
`--id` — короткое имя документа латиницей (`reglament`, `otchet-2026-09`), одно и то же для всех его версий: перед добавлением посмотри `versions.py list`. `--type` — вид документа (регламент, отчёт, выгрузка).
При правке в хранилище кладётся сначала исходная версия (до правки), затем новая. Сгенерированный по шаблону документ тоже кладётся — первой версией. Какая версия считается действующей — решает человек.

## Выход и связи
- Готовые файлы — `hub/docs/out/`.
- Заявке в `hub/handoff/` поставь `status: done` и допиши «Результат»: файлы, отчёт валидатора, что осталось незаполненным.
- Если правка меняет факт, записанный в базе (срок, сумму, ответственного) — запиши расхождение в `hub/kb/_противоречия.md` (формат — плейбук №2); при отдельном запуске, вне «Моего дня», ещё и заявка Библиотекарю `to: kb`, `needs: any`: завести заметку о новой версии. Строки противоречий закрывает только человек.
- Работа с Excel «в помощь человеку» (формула, сводная, Power Query, макрос) — выдай готовое решение текстом, человек применит в своём Excel.

## Самопроверка
Отчёт валидатора приложен; незаполненных меток нет или они перечислены; исходник не изменён.

## Что остаётся человеку
Утвердить итоговый документ и решить, какая версия становится актуальной.
