# Практика «Личные агенты» — корень репозитория

Пять треков в двух мирах. **Мир Claude** — `1_claude/` (ассистенты работают на Claude): кейсы `01_digest`…`05_docs` —
это трек 1 (тематические ассистенты, выбирается один), кейс `06_assistant` — трек 2 (оркестратор над ними). **Мир
Hermes** — `2_hermes/` (Claude собирает ассистентов для Hermes Agent): кейс `01_digest` + `BUILD.md` — трек 3
(тематический Hermes-ассистент), `orchestrator/` — трек 4 (оркестратор над флотом Hermes, в т. ч. удалённым),
`manual/` — трек 5 (универсальный Hermes-ассистент, собирается руками без Claude). Общий пак — `skills_pack/`.
Полная карта — в `README.md`.

- Работать с кейсом — открыть его папку как проект: у кейсов мира Claude свой `CLAUDE.md`, свои `.claude/agents` и
  `.claude/skills`; у кейсов мира Hermes — `AGENTS.md` и `.hermes/skills`.
- **Собрать нового Hermes-ассистента** (трек 3) — в `2_hermes/` по `BUILD.md`: предложить формой один из пяти готовых
  сценариев или «опишу своего». Оркестратор над Hermes (трек 4) — работать в `2_hermes/orchestrator/` по её `CLAUDE.md`.
- Источник правил кейса — `playbooks/`. Файлы в `.claude/`, `.hermes/`, `AGENTS.md`, `cowork-plugin/`, `dist/`, `pack/`
  собираются скриптами, руками их не править: `python tools/build.py` в папке кейса; пак — `python skills_pack/sync.py`;
  общие скрипты и учебные данные мира Hermes — `python 2_hermes/sync.py`. **Исключение — трек 5** (`2_hermes/manual/`):
  там заготовки в `templates/` собраны вручную, сборки нет — это сделано намеренно, их правят руками.
- Личных данных в репозитории нет. Папки `hub/` и `.secrets/` в git не попадают; содержимое `.secrets/` не читать.
- `1_claude/06_assistant/tools/install.py` без пути обновляет установленного ассистента владельца — запускать только
  по его просьбе.
