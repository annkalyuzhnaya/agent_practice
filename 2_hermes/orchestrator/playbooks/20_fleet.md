# Флот — реестр ассистентов и как их поднимать

Флот — список тематических ассистентов Hermes, которыми оркестратор дирижирует. Он хранится в `hub/fleet.json`.
Каждый ассистент — отдельная папка-кейс Hermes (трек 3), со своей моделью и своей шиной `hub/`.

## Формат `hub/fleet.json`

```json
{
  "_": "Флот оркестратора. Ключей API здесь нет — они живут у Hermes на каждой машине.",
  "assistants": [
    {
      "name": "обозреватель",
      "role": "digest",
      "skill": "digest",
      "where": "local",
      "path": "D:/Hermes/Обозреватель",
      "host": "",
      "model": "",
      "provider": "",
      "deliver": "hub",
      "reads": "hub/digest/",
      "note": "дайджест по темам; поднимать утром"
    }
  ]
}
```

| Поле | Что значит |
|---|---|
| `name` | как владелец называет ассистента в чате |
| `role` | короткий код роли: `digest`, `kb`, `meeting`, `inbox`, `docs`, `assistant` (универсальный помощник трека 5) или свой |
| `skill` | имя навыка Hermes в папке ассистента (для запроса) |
| `where` | `local` (эта машина) или `remote` (другой хост — см. `30_remote.md`) |
| `path` | абсолютный путь к папке ассистента — вне папки практики `agent_practice` (внутри неё Hermes не найдёт навыки ассистента). Для `remote` — путь на том хосте |
| `host` | для `remote`: как достучаться (строка SSH `user@host`, имя облачной папки или `telegram`) |
| `model`, `provider` | модель этого ассистента; пусто — модель Hermes по умолчанию |
| `deliver` | как возвращается результат: `hub` (читаю его шину), `folder` (общая папка), `telegram` |
| `reads` | где на его шине лежит свежий результат (какую папку читать) |
| `note` | заметка владельца |

## Поднять локального ассистента

1. Собери задачу: что сделать, какой файл результата создать, на какие правила опереться. Дочерний процесс Hermes
   начинает с чистого листа — поэтому в задаче явно назови навык и файл результата.
2. Запусти Hermes в **его** папке (его `path` — это `cwd`):
   ```bash
   hermes chat -q "<задача>" --model "<model>" --provider "<provider>"
   ```
   (поля `--model`/`--provider` добавляй, только если они заданы в `fleet.json`).
   Точную строку под каждого ассистента печатает `python tools/fleet.py show`.
3. Прочитай свежий файл в `<path>/<reads>`, скопируй нужное в свою `hub/results/ГГГГ-ММ-ДД_<role>.md` с шапкой
   (`from`, `source`), сошлись на него в плане.

Ассистента нет в среде (папки нет, `hermes` не найден) — не выдумывай результат: отметь в плане и предложи проверить
путь или собрать ассистента (трек 3, `../BUILD.md`).

## Поднять удалённого ассистента

По `30_remote.md`. Коротко: `where: remote` → смотри `host`. Удалённую команду запускай только после «да» владельца
на точный текст.

## По расписанию ассистент поднимается сам

Если у ассистента есть задание `hermes cron`, он делает выпуск сам и доставляет его (`deliver`). Оркестратор тогда
не поднимает его повторно — только забирает свежий выпуск с его шины (или из общей папки / Telegram) и сводит в план.
Создание и изменение cron — в папке самого ассистента, не здесь.

## Управление флотом

- **«Покажи флот»** → `python tools/fleet.py show` (кто есть, где живёт, какой моделью, как поднимается) или прочитай
  `hub/fleet.json` и перескажи таблицей.
- **«Добавь ассистента …»** → спроси формой роль, путь (или хост), модель и доставку; допиши запись в `hub/fleet.json`.
  Проверь, что путь существует (локальный) или хост отвечает (удалённый, `30_remote.md`).
- **«Убери ассистента …»** → удали запись из `hub/fleet.json` (папку ассистента не трогай).
- **«Проверь флот»** → `python tools/fleet.py check`: для локальных — есть ли папка и `hermes`; для удалённых —
  отвечает ли хост (только после «да» на проверочное подключение).
