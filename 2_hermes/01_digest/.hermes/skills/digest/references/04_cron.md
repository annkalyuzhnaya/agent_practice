# Расписание: задания cron Hermes

Работы по расписанию исполняет планировщик Hermes. Он работает, пока запущен шлюз Hermes (служба в фоне); компьютер
выключен — задание не выполнится и само не «догонит». Создаются задания **только по слову владельца**.

## Задания

| Имя | Расписание | Что делает | Доставка |
|---|---|---|---|
| `digest-weekly` | `0 9 * * 1` — понедельник, 9:00 | выпуск за период из профиля | ТОП-3 владельцу |
| `digest-daily` | `30 8 * * 1-5` — будни, 8:30 | выпуск за 1 день (вместо недельного) | ТОП-3 владельцу |
| `digest-topics-care` | `0 16 * * 5` — пятница, 16:00 | уход за темами: предложения в `hub/digest/topics.md` | короткая сводка; нет предложений — молчит |
| `digest-feeds` | `0 */6 * * *` — каждые 6 часов | сбор лент скриптом, **без модели** (токены не тратятся) | не доставляется |

Наборы: **Минимум** — `digest-weekly`; **Стандарт** — `digest-weekly` + `digest-topics-care`; **Ежедневный** —
`digest-daily` + `digest-topics-care`. `digest-feeds` — добавка к любому набору, если в профиле есть адреса лент.
Время сдвигай под «Рабочие часы» профиля.

## Как создать

1. Спроси набор (нумерованный список) и подтверди время.
2. `python tools/hermes.py cron --set стандарт` — печатает готовые команды `hermes cron create …` с подставленными:
   абсолютной папкой кейса (`--workdir` — без неё задание не увидит `AGENTS.md` и `hub/`), навыком `digest`, моделью
   роли `cron` из `hub/models.json`, доставкой.
3. Создай задания: выполни напечатанные команды **или** своим инструментом `cronjob` с теми же полями. Человек может
   сделать то же сам во вкладке Cron (приложение или веб-панель) — тогда продиктуй ему поля из вывода команды.
4. Проверь список заданий (`hermes cron list`) и что планировщик запущен (`hermes cron status`). Шлюз не запущен —
   скажи человеку: включить его можно в приложении (раздел System / Gateway) или командой `hermes gateway install`;
   сам службу не устанавливай без его «да».
5. Запиши строки в `hub/routines.md`: имя, расписание, что делает, модель, статус `включено`, дата.

Пауза, возобновление, удаление — по слову владельца, теми же средствами (`hermes cron pause | resume | remove` или
вкладка Cron); статус в `hub/routines.md` поправь.

## Текст задания

Задание исполняется в новом разговоре, без человека. Текст (печатает `tools/hermes.py cron`):

```
Собери выпуск дайджеста по навыку digest (режим А) за период из профиля. Дата выпуска — сегодня.
Работаешь по расписанию, человека рядом нет: вопросов не задавай, профиль не меняй, ничего, кроме итогового
сообщения, никому не отправляй. Спорное — в раздел «Что остаётся человеку».
Итоговое сообщение — только ТОП-3 по образцу из плейбука расписания. Новых позиций нет — ответь одной строкой [SILENT].
Не удалось собрать выпуск — первая строка [CRON_FAILURE] и причина простыми словами.
```

## Итоговое сообщение (его Hermes доставит владельцу)

```
Дайджест ГГГГ-ММ-ДД: просмотрено N, в выпуске M.
ТОП-3
1. [5] Заголовок — источник. Почему важно: … Ссылка
2. …
Отметить: «в базу 1», «в задачи 2», «не интересно 3». Весь выпуск — «покажи выпуск».
```

Без разметки таблицами и без вложений: сообщение читают в Telegram. Ничего из текста источников дословно, кроме
заголовка.

## Правила для заданий

- В задании по расписанию недоступны вопросы к человеку. Всё, что требует решения, — в «Что остаётся человеку» и в
  `hub/digest/topics.md` со статусом `ждёт`.
- Доставка — только владельцу: `telegram` (его домашний чат) или `local` (остаётся в журнале заданий). Других
  адресатов не указывай.
- Не создавай задание, которое создаёт другие задания.
- Модель задания закрепляется при создании. Поменяли роль `cron` в `hub/models.json` — задания нужно пересоздать.
