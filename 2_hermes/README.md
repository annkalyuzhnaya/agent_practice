# Мир Hermes — треки 3, 4 и 5

Не у каждого есть подписка Claude для ежедневной интенсивной работы. Этот мир показывает другой способ применить
Claude — как **разработчика** личных ассистентов, которые потом работают в открытой среде Hermes Agent на любых
моделях по ключу API, — и доводит до сборки своими руками без Claude.

| Трек | Папка | Суть |
|---|---|---|
| **3** | `2_hermes/` + [`BUILD.md`](BUILD.md), образец [`01_digest`](01_digest/README.md) | Claude собирает **тематического** Hermes-ассистента: один из 5 готовых сценариев или свой |
| **4** | [`orchestrator/`](orchestrator/README.md) | Claude-**оркестратор** над флотом Hermes-ассистентов (локальных и удалённых) |
| **5** | [`manual/`](manual/README.md) | **универсальный** Hermes-ассистент, собранный **руками, без Claude**, по инструкции для не-программистов |

Мир Claude (треки 1 и 2) — в [`../1_claude/`](../1_claude/README.md).

## Что здесь

| Путь | Что это |
|---|---|
| [`BUILD.md`](BUILD.md) | рецепт трека 3: как Claude собирает любого тематического Hermes-ассистента (5 сценариев или свой) |
| [`01_digest/`](01_digest/README.md) | готовый кейс-образец (Обозреватель): по нему собирается любой новый кейс трека 3 |
| [`orchestrator/`](orchestrator/README.md) | трек 4: Claude-оркестратор над несколькими Hermes-ассистентами |
| [`manual/`](manual/README.md) | трек 5: `START.html` + `MANUAL.md` + заготовки `templates/` для сборки руками |
| `CLAUDE.md` | правила этой папки-мастерской: что делать, когда человек просит собрать ассистента |
| `sync.py` | переносит в кейсы трека 3 среда-независимые скрипты и данные из мира Claude |

**Собрать нового тематического ассистента** (трек 3): откройте `2_hermes/` в Claude и напишите «собери ассистента для
Hermes» — Claude поведёт по `BUILD.md` (форма с пятью сценариями или «опишу своего»).

Новичку в готовом кейсе: `START.html` — руководство со снимками веб-панели Hermes (открывается двойным щелчком).
Установку и команды выполняет Claude по готовому запросу; человек вводит ключ API и отвечает на вопросы настройки.

`sync.py` переносит в кейсы трека 3 то, что от среды не зависит (скрипты, учебные данные, заготовки `hub/`), из
кейсов мира Claude — чтобы каждая папка оставалась самодостаточной и ничего не правилось в двух местах. Папки
`orchestrator/` и `manual/` свой источник в мире Claude имеют не целиком, поэтому `sync.py` их не трогает.

## Три идеи трека

1. **Правила отделены от среды.** Плейбуки, скрипты и данные переезжают почти без изменений; меняется только
   упаковка (`AGENTS.md` и навыки вместо `.claude/`) и то, чем исполняются роли.
2. **Модель под роль.** Редактор, разведчики, проверяющий и расписание могут работать на разных моделях разных
   провайдеров. Выбор делается приёмкой на учебном наборе и подтверждается ценой.
3. **Окно, а не терминал.** Слушатель работает в приложении Hermes Desktop или веб-панели: чат, выбор модели,
   расписание, Telegram, расход — кнопками.

## Чем заменено то, что было в Claude

| В Claude | В Hermes |
|---|---|
| `CLAUDE.md` | `AGENTS.md` (у Hermes он важнее `CLAUDE.md`, если есть оба) |
| навыки `.claude/skills`, плагин Cowork | навыки `.hermes/skills/` (формат agentskills.io), подключаются, когда папка кейса — проект git и выполнено `hermes skills trust` |
| субагенты | `delegate_task` — дочерние агенты с чистым контекстом, одна модель на всех |
| независимый проверяющий-субагент | отдельный запуск Hermes на другой модели |
| формы `AskUserQuestion` | `clarify` с нумерованными вариантами |
| страница-артефакт с хранилищем | локальный HTML из файлов `hub/`, предпросмотр в приложении |
| запланированные задачи | `hermes cron` с моделью, закреплённой за заданием, и доставкой в Telegram |
| скрипт-мост Telegram | шлюз Hermes |
| веб-поиск Claude | веб-инструменты Hermes (поисковый сервис подключает владелец) |

## Навыки пака: что идёт в Hermes

Навык из `skills_pack/` попадает в кейс этого трека, если выполнены оба условия: на него опирается плейбук кейса и
в среде Hermes нет своего средства для той же работы. Раскладка — в `skills_pack/manifest.json` (ключи `2_hermes/…`).

| Навык | В Hermes | Почему |
|---|---|---|
| `internal-comms`, `build-dashboard` | да (кейсы 1, 3–6) | чистые приёмы письма и вёрстки, от среды не зависят; более слабым моделям явный формат полезнее, чем Claude |
| `data-visualization`, `validate-data` | да (кейс 5) | то же: приёмы и Python |
| `memory-management`, `task-management` | после адаптации (кейсы 2–4, 6) | словарь владельца и задачи нужны, но навыки пишут в `CLAUDE.md` и `TASKS.md`; у Hermes своя память — без правки будет два источника правды |
| `tavily-*` | нет | у Hermes свои веб-инструменты; поисковый сервис подключается в его настройках, второй путь к тому же поиску только путает модель |
| `start`, `update` | нет | доска и коннекторы плагина Productivity; в Hermes их роль у страницы кейса и раздела Cron |
| `skill-creator` | нет | работает через Claude Code; в этом треке навыки создаёт Claude, а в Hermes попадает результат |
